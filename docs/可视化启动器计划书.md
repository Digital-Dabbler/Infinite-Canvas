## 一、我理解的三个痛点

| 痛点 | 现状 | 启动器要做到 |
| --- | --- | --- |
| ① 改完代码重启麻烦 | 先关掉终端窗口，再去文件夹双击 `启动服务.bat` | 启动器窗口里点【重启】，一步完成；服务在后台跑，**平时不需要常开终端** |
| ② 拉取 GitHub 更新麻烦 | 在别的机器改了并推送后，本机要开 GitHub Desktop 或敲命令拉取 | 点【检查更新】→ 显示 GitHub 上你的分支比本机多了哪些提交 → 点【一键更新】拉下来 |
| ③ 更新偶尔冲突，不好处理 | 冲突后要手动解决，心里没底 | 更新前自动留备份；冲突时逐文件显示，可选「保留我的 / 用新版」，也可批量一键选边；处理不了点【撤销更新】回到更新前 |

一句话：**把"终端 + 文件夹双击 + GitHub Desktop"三件事收进一个窗口。**

## 二、更新源头（已按你的更正定稿）

- 你已不跟原作者走：从 hero8152 fork 后一直在**自己的 origin 仓库（Digital-Dabbler）的当前分支**上开发推送，其他机器也拉这个分支。
- 所以启动器的更新逻辑 = **对 origin 同步**：
  - 【检查更新】= `git fetch origin`，对比"本机当前分支"和"GitHub 上同名分支"：落后 → 列出多出的提交；领先 → 提示"有 N 个提交未推送，建议点【备份我的改动】"。
  - 【一键更新】= 把 `origin/当前分支` 合并进本机当前分支（通常能直接快进；两边都改过就走合并，冲突进冲突界面）。
  - 【备份我的改动】= 把当前分支 push 到 origin。
  - 合并前自动记录备份点，任何时候可【撤销更新】。
- 本机 git 里残留的 `upstream`（原作者）remote 启动器**不使用、不显示**。

## 三、窗口布局（参考你截图的信息组织方式）

单窗口仪表盘，从上到下三块：

1. **状态卡片区**
   - 服务状态灯：运行中 / 已停止 / 启动中（绿/灰/黄），本机地址 `http://127.0.0.1:3000` 与局域网地址，【打开工作台】按钮。
   - 版本卡片：当前版本（读 `VERSION`）+ 提交号 + 同步状态（已同步 / 落后 N / 领先 N）。
   - 环境卡片：内置 Python 是否正常、端口 3000 是否被外部程序占用。
2. **操作区**
   - 服务：【启动】【停止】【重启】。停止/重启只认本项目目录启动的 python 进程（沿用已实测的 daily-restart 安全判定），同机 ComfyUI 等其它 python 绝不误杀。
   - 更新：【检查更新】【一键更新】【撤销更新】【备份我的改动到 GitHub】。
   - 冲突界面（仅更新出冲突时出现）：每个冲突文件一行，展示两边改动摘要，按钮【保留我的】【用新版】；顶部批量按钮【全部保留我的】【全部用新版】（点击弹二次确认，防手滑）；底部【撤销整个更新】。
3. **日志区**
   - 实时滚动服务输出（启动报错、访问日志），服务输出由启动器接管写入 `logs\launcher_server.log`。

**打开行为（已定稿）**：双击 `启动器.bat` → 窗口出现 → 若服务没在跑**自动启动**（日志照常进窗口）；若已在跑只显示状态。

## 四、界面形态（A/B 说明，等你选）

- **A. 本地网页控制台（推荐）**：新增 `tools\launcher\launcher.py`（Python 标准库，不新增依赖），在本机 `127.0.0.1:3100` 起一个只有你自己机器能访问的页面 `launcher.html`，用 Edge"应用模式"打开成**没有地址栏的独立窗口**。质感接近你发的 ComfyNexus 截图：深色背景、圆角卡片、状态灯、实时日志滚动。以后加功能不改架构。
- **B. 传统 Windows 原生窗口（PowerShell WinForms）**：一个 `launcher.ps1` 直接弹系统窗口。长这样：浅灰底、方形系统按钮、普通列表框和文本框，类似"控制面板/任务管理器"那种 Windows 自带软件的观感——能用、更轻量（不起本地网页服务），但做不出截图那种深色卡片质感，字体和排版也朴素。
- 两者都不需要联网安装东西。你截图里那种效果对应 A。

## 五、内置"文件覆盖式在线更新"接口 → 建议删除（你的提问的回答）

项目后端有一整套从原作者仓库**直接下载文件覆盖本地**的更新机制，但前端没有任何界面调用它（死代码），且写死 hero8152、覆盖式更新会把我们本地定制盖掉。**推荐删除而非改造**——它的备份/回滚职责由启动器的 git 备份点替代，git 通道与你的 fork 工作流一致。

删除范围（main.py，约 3290-3913 区间内仅被这套接口使用的部分）：
- 路由 5 个：`/api/update-connectivity/probe`、`/api/update-connectivity`、`/api/update-from-github`、`/api/update-backups`、`/api/update-rollback`。
- 专用 helper：`update_connectivity_targets/probe`（更新连通性部分）、`update_allowed_file`、`github_get`、`github_json`、ModelScope/GitHub 文件抓取与暂存函数、`schedule_self_restart`（仅被这两个更新路由使用）、`github_update_file_list`、`staged_update_file_list`、`list_update_backups`、`normalize_update_source`、`UPDATE_SOURCE_LABELS`、`read_local_update_notes`。
- 常量：`GITHUB_TREE_URL`、`GITHUB_RAW_ROOT`、`GITHUB_UPDATE_NOTES_URL`、`MODELSCOPE_TREE_URL/FILE_API_ROOT/UPDATE_NOTES_URL/VERSION_URL/REPO_URL` 等仅更新用项。
- **保留**：`/api/app-info`（canvas-list.js 和 studio-shell.js 靠它拿 `version/canvas_static_version` 做缓存戳，必须留），只把其中的 `sources`、`tree_url`、`update_notes` 等更新字段去掉；`repo_url` 改指向你的 origin fork。
- 连带：AGENTS.md 里"更新回滚"管理员职责一句同步删除；`data/update_backups/` 旧备份目录属运行时数据不动；`static/update-notes.json` 留着无害（不再被读）。
- 实现时以 grep 全量核对调用点为准，删完跑全量测试确保无悬挂引用。

## 七、安全与边界

- 启动器只监听 `127.0.0.1`，局域网同事访问不到。
- 停止服务只杀"可执行文件位于本项目 python\ 目录"的进程，绝不误伤 ComfyUI 等其它程序。
- 更新全部基于 git：合并前留备份点，失败可一键撤销；push 只推当前分支到 origin，绝不自动 force。
- 未提交的运行时噪声（素材库状态、静态缓存戳）更新前自动暂存、更新后自动放回；放回有冲突同样进冲突界面。
- 关闭启动器窗口不影响正在运行的服务；【退出启动器】按钮做干净收尾。
- 不做（v1 范围外）：多环境管理、插件/LoRA/依赖市场、AI 助手。
