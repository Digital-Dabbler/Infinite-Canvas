# 部门独立 API 配置组：阶段验收与隔离测试方案

> 文档状态：草案
> 目标：为每个改造阶段设置可验证、可停止、可回滚的退出条件
> 原则：假上游和自动化测试优先，真实付费平台只做单次低成本冒烟
> 最后更新：2026-08-01

## 0. 当前自动化覆盖

已新增 `tests/test_api_profiles.py`，当前覆盖：

- 首次兼容迁移与重复执行；
- 迁移后新注册用户不会被自动授权；
- 损坏和未知版本文件使用只读兼容回退；
- 配置组复制不包含凭据；
- 管理员为用户分配配置组；
- 同平台 ID 在不同配置组解析出不同测试凭据；
- 当前组缺少明确平台时拒绝，不跨组回退；
- 未分配用户无法解析付费配置组；
- 普通用户公开结构不包含密码字段。

尚未执行本文件要求的完整假上游并发、失败注入、页面手工验收和真实平台低成本冒烟，因此相关验收项仍保持未勾选。

## 1. 验收原则

1. 每个阶段先满足进入条件，再开始修改。
2. 每个阶段完成后必须通过退出条件，才能进入下一阶段。
3. 隔离测试失败时立即停止后续迁移，不以“前端看起来正常”代替修复。
4. 自动化测试主要使用本地假上游，不默认消耗真实余额。
5. 测试同时覆盖正常路径和伪造请求、并发、失败、刷新恢复等负面路径。
6. 每次测试记录代码版本、数据版本、配置组、用户、结果和证据。
7. 工作区已有修改、运行时数据和密钥不得混入功能提交。
8. 不能自动验证的外部服务必须明确记录限制、风险和人工验证步骤。

## 2. 测试环境与固定数据

### 2.1 测试配置组

建议建立四个仅用于测试的配置组：

| 配置组 | 稳定 ID | 假凭据标识 |
| --- | --- | --- |
| UI测试账户 | `test-ui` | `TEST_KEY_UI_ONLY` |
| 原画测试账户 | `test-art` | `TEST_KEY_ART_ONLY` |
| 视频测试账户 | `test-video` | `TEST_KEY_VIDEO_ONLY` |
| 市场测试账户 | `test-marketing` | `TEST_KEY_MARKETING_ONLY` |

假凭据只能用于本地测试，不得与真实密钥格式混淆，也不得进入正式配置。

### 2.2 测试用户

| 用户 | 部门 | 配置组 | 角色 |
| --- | --- | --- | --- |
| `test_ui_user` | UI组 | `test-ui` | user |
| `test_art_user` | 原画组 | `test-art` | user |
| `test_video_user` | 视频组 | `test-video` | user |
| `test_marketing_user` | 市场组 | `test-marketing` | user |
| `test_unassigned_user` | 待确认 | 空 | user |
| `test_profile_admin` | 管理 | 管理员上下文 | admin |

测试用户和会话不得写入正式运行数据或提交到仓库。

### 2.3 假上游服务

假上游至少应支持：

- 记录请求时间、路径、方法和非敏感测试标识；
- 检查 Authorization属于哪个测试配置组；
- 模拟同步成功；
- 模拟异步提交、运行中、成功和失败；
- 模拟 401、403、429、500和超时；
- 模拟模型列表；
- 模拟图片、视频和 LLM响应；
- 模拟 RunningHub钱包与普通 Key差异；
- 模拟火山 API Key和AK/SK路径；
- 在测试失败时输出脱敏诊断。

假上游日志不得输出真实部署凭据。

## 3. 阶段通用验收记录

每个阶段结束时填写：

```text
阶段：
代码版本/提交：
数据格式版本：
修改文件：
已处理入口：
未处理入口：
自动测试：
手工验证：
测试证据：
发现风险：
设计决定：
回滚方式：
是否满足退出条件：
验收人：
日期：
```

缺少“未处理入口”或“回滚方式”的阶段不得直接进入下一阶段。

## 4. M0：基线与备份验收

### 4.1 进入条件

- 已阅读仓库协作说明；
- 已检查 Git 状态；
- 已识别用户已有修改；
- 未启动可能重写静态缓存戳或运行时数据的服务。

### 4.2 验收项目

- [ ] 记录当前分支、提交和工作区状态；
- [ ] 备份用户、会话、平台配置、用量策略和必要运行数据；
- [ ] 备份位置不在源码提交范围；
- [ ] 不打印、不复制真实密钥到报告；
- [ ] 记录登录、平台列表、图片、视频、LLM和异步任务的现有行为；
- [ ] 记录当前已知失败或外部服务不可用情况；
- [ ] 完成初版入口清单；
- [ ] 验证当前 Python与JavaScript语法基线。

### 4.3 退出条件

- 可以区分基线问题与新回归；
- 有明确恢复用户和平台配置的方法；
- 入口清单覆盖所有已知平台族。

## 5. M1：兼容数据模型验收

### 5.1 核心目标

引入配置组结构，但所有现有用户仍使用“现有共用账户”，不改变实际调用结果。

### 5.2 自动测试

- [ ] 无新配置文件时能从旧平台配置启动读取；
- [ ] 首次迁移创建且只创建一个 `legacy-shared`；
- [ ] 迁移重复执行不会重复配置组或用户绑定；
- [ ] 旧用户自动绑定兼容组；
- [ ] 管理员账号不会因迁移失去权限；
- [ ] 旧平台顺序、默认平台、模型和启停状态不变；
- [ ] 特殊平台字段完整保留；
- [ ] 损坏或未知版本配置产生可读错误或安全回退；
- [ ] 保存、重新读取结果一致；
- [ ] 密钥不会写入非敏感配置文件。

### 5.3 手工验证

- [ ] 旧账号登录；
- [ ] API 设置页展示与基线一致；
- [ ] 普通画布和智能画布加载；
- [ ] 旧画布的平台、模型选择保持；
- [ ] 低风险假上游调用行为与改造前一致。

### 5.4 退出条件

- 数据结构已经具备配置组能力；
- 生产行为仍等价于单一全局配置；
- 迁移可重复、可备份恢复。

### 6.2 UI 测试

- [ ] 切换组后平台列表正确；

### 6.4 退出条件

- 没有普通用户可利用的配置组修改入口。

## 7. M3：服务端隔离核心验收

### 7.1 同平台不同凭据

四个测试配置组都建立同名平台 `test-openai`，分别绑定不同假凭据。

- [ ] UI用户请求上游只出现 `TEST_KEY_UI_ONLY`；
- [ ] 原画用户请求上游只出现 `TEST_KEY_ART_ONLY`；
- [ ] 视频用户请求上游只出现 `TEST_KEY_VIDEO_ONLY`；
- [ ] 市场用户请求上游只出现 `TEST_KEY_MARKETING_ONLY`；
- [ ] provider ID相同不会导致凭据覆盖；
- [ ] 保存一个配置组不会改变其他组凭据状态。

### 7.2 伪造与越权

- [ ] 普通用户提交其他组 `api_profile_id` 被忽略或拒绝；
- [ ] 普通用户修改 Cookie之外的普通请求字段不能换组；
- [ ] 普通用户请求其他组独有 provider被拒绝；
- [ ] 普通用户请求其他组独有模型被拒绝或按本组规则校验；
- [ ] 普通用户不能通过模型拉取接口探测其他组；
- [ ] 普通用户不能利用测试连接接口提交任意 Key/Base URL；
- [ ] 扩展 Token仍只能代表所属用户；
- [ ] 管理员的组选择只影响管理操作，不形成全局当前组。

### 7.3 回退规则

- [ ] 未提供 provider时使用本组 primary；
- [ ] 明确 provider不存在时返回错误；
- [ ] 明确 provider已禁用时返回错误；
- [ ] 本组所有平台禁用时不调用共享或其他组；
- [ ] 共享服务只有显式启用时可使用；
- [ ] 上游401/429/500不会切换到其他配置组。

### 7.4 并发隔离

并发发起至少四组请求，交错模拟慢响应：

- [ ] 每个请求的 Authorization与用户一致；
- [ ] 多轮并发没有全局当前组污染；
- [ ] 一个组保存配置时不改变正在执行的其他组请求；
- [ ] 一个组密钥轮换不影响其他组；
- [ ] 一个组出现超时不触发其他组兜底；
- [ ] 日志可以按请求定位，但不包含真实凭据。

### 7.5 退出条件

- 所有核心隔离自动测试通过；
- 代码中不存在按请求修改全局密钥的实现；
- 统一解析层有清晰、稳定的调用契约。

这是进入真实生成链路迁移前的强制门槛。

- [ ] 异步任务验证；
- [ ] 上游账单验证；
- [ ] 用量后台验证；
- [ ] 异常与回滚记录。

### 11.4 旧账户退役

- [ ] 所有正式用户已离开兼容组，或有明确保留原因；
- [ ] 兼容组不再产生新费用；
- [ ] 旧共用密钥已停用或轮换；
- [ ] 不把已暴露风险的旧密钥作为回滚手段；
- [ ] 观察至少一个发布周期；
- [ ] 再删除确认无调用的旧兼容代码。

## 12. 真实平台冒烟原则

真实付费测试必须：

- 由管理员明确执行；
- 每个平台只做必要的单次最低成本请求；
- 图片使用最低质量或自动尺寸；
- 视频使用最短时长和最低支持分辨率；
- 先检查余额与平台状态；
- 不批量测试四个部门的所有模型；
- 记录测试配置组、平台、模型、时间和上游任务 ID；
- 不在报告中记录真实密钥；
- 测试后核对系统审计和上游账单。

没有网络、余额、登录会话或外部服务时，应记录“未执行”及原因，不能用推测替代通过。

## 13. 安全检查

每个阶段至少执行：

- [ ] 检查 Git diff中没有 API Key、Token、Cookie、AK或SK；
- [ ] 检查响应样例中没有密钥、变量名和其他组信息；
- [ ] 检查日志和异常中没有 Authorization；
- [ ] 检查任务与画布 JSON中没有凭据；
- [ ] 检查工作流 JSON/ZIP中没有凭据；
- [ ] 检查普通用户不能调用管理员平台管理接口；
- [ ] 检查注册部门不能直接获得付费权限；
- [ ] 检查用户禁用、退出、改密和 Token撤销仍会使旧会话失效；
- [ ] 检查目录、文件名、归档和共享路径安全逻辑未被削弱。

## 14. 回归检查

配置组改造不能破坏：

- 登录、注册、改密和管理员权限；
- 普通画布与智能画布保存兼容；
- 图片、视频、LLM节点；
- 智能画布级联、循环和恢复；
- 画布导入导出；
- 素材库和提示词库；
- RunningHub钱包兼容；
- ComfyUI工作流；
- Chrome素材采集；
- Photoshop素材面板；
- WebSocket应用层心跳和重连；
- 媒体预览、下载和认证；
- 明暗主题和中英文文本。

## 15. 停止条件

出现以下任一情况，应停止进入下一阶段：

- 同一用户请求可能解析到多个配置组；
- 并发测试出现密钥串用；
- 普通用户能影响 `api_profile_id`；
- 异步任务无法确定提交配置组；
- 明确平台不存在时发生跨组回退；
- 密钥出现在响应、日志、任务或 Git diff中；
- 管理员保存一个组会覆盖其他组；
- 旧用户或旧画布无法安全迁移；
- 无法说明当前阶段的回滚方式；
- 入口清单存在未评估的付费路径；
- 自动测试失败但仅以手工页面正常作为放行依据。
