# 遮罩编辑器迁移计划书（v1 · 待你确认）

> 目标：把 ComfyUI 里 Goohaitools 的遮罩编辑器那套"画遮罩的方式"搬到智能画布，顶替现在画布里的遮罩工具。
> 本文只讲方案与理解，不改代码。你先看"一、我理解的需求"，理解偏了我改。

## 一、我理解的需求

| 你的原话 | 我的理解 |
| --- | --- |
| "把图2那种绘制遮罩的方式迁移到画布" | 图2 是 Goohaitools 的遮罩编辑器（`goohai_mask_editor.js`，3654 行）：**独立全屏画布**，顶部一条工具带、左上一个输出小面板，中间就是图片本身。要的是这套工具与手感，不是照搬它的界面配色 |
| "顶替掉原来的画遮罩的方式" | 现在画布里的遮罩：弹窗内切"遮罩"模式，只能画笔/橡皮擦/黑白叠加色/撤销/清空，导出一张纯黑白 PNG。这套整体退休，换成新的 |
| "先出一份计划书，我看下你对需求的理解" | 先确认理解与边界，再动手；不在这轮写代码 |

一句话：**画布点"遮罩"，进入一个专注画遮罩的全屏编辑器，工具与手感对齐 Goohai 那套，保存后仍按老规矩挂在这张图片上。**

## 二、Goohai 那套到底强在哪（我读过它的实现）

| 能力 | 具体表现 |
| --- | --- |
| 三种工具 | 画笔（B）、橡皮擦（E）、**选框（M）**：拖出新框；按住 Shift 追加；按住 Alt 减掉；第一次按 Shift 拖出正方形；在框内拖动可整体平移选框；点框外清空选框 |
| 笔刷大小 | 顶部显示当前 px（2–300）；**鼠标右键左右拖动**即可调大调小（不用去摸滑杆）；也有 `[` `]` 每次 ±5；按住 Alt 临时变橡皮 |
| 撤销/重做 | 完整历史栈，Ctrl+Z / Ctrl+Shift+Z |
| 反转 / 清空 | 一键反选遮罩（Ctrl+I）、一键清空（X） |
| **自动填充漏洞** | 笔画围出的空洞自动补实（免去反复涂抹），左面板开关 |
| **仅遮罩 / 颜色叠加** | 两种输出：①纯黑白遮罩（叠在原图上固定 50% 透明度）；②在原图上叠一层可调透明度的彩色遮罩（9 色可选，每色一层，可分别画不同区域，右键已涂处可改色/删掉那一块） |
| 看图手感 | 滚轮**以光标为中心**缩放（5%–1200%），Space/中键拖动画布——画大图细节时不用来回滚动页面 |
| 专注形态 | 全屏、隐藏画布其它 UI、Esc 取消、Enter 保存 |

**关键实现细节（决定迁移难度）**：

- 编辑时把图缩到长边 **1536** 再画（省性能），保存时按原图尺寸一次性放大，放大用最近邻（不糊边、不产生灰边）。
- 手绘层是"真值"，填洞层只是"显示/保存视图"，两者分开存，所以重开时还能重新关掉填充看原始笔迹。
- **反转不改像素**，只翻一个"反转中"的开关标志，导出时才生效——省一次全图运算，这个设计要照搬。
- 多色层用自定义 PNG 数据块塞进同一张 PNG，重开能还原每层颜色。
- 但它的历史栈是**整幅像素快照 × 50 张**（1536×1536 每张约 9MB，最坏几百 MB）。这一点我们**不照搬**，改用更省的方式（见第四节）。

## 三、现状对照（画布现在有的 / 迁移后有的）

| 能力 | 现在画布 | 迁移后 |
| --- | --- | --- |
| 入口 | 图片编辑弹窗 → 模式条选"遮罩" | 顶部工具栏"遮罩"按钮直接进编辑器（见决策 1） |
| 工具 | 画笔、橡皮擦 | 画笔、橡皮擦、选框 |
| 笔刷大小 | 滑杆 4–160 + `[` `]` | 滑杆 + 右键拖动 + `[` `]` |
| 撤销/重做 | 有 | 保留 |
| 反转 | 无 | 新增 |
| 自动填充漏洞 | 无 | 新增 |
| 输出 | 只有黑白遮罩 | 黑白遮罩 +（可选）彩色叠加图 |
| 多色层 | 无 | 见决策 2 |
| 遮罩归属 | 挂在 `node.images[i].mask`（`{url,name,kind}`），上传成素材，生成时以 `mask_url` 发出 | **不变**（这是最重要的兼容点） |

再补三条现状事实（决定迁移成本）：

- 画布现在的遮罩画布其实是**原图分辨率**（`resizeEditDrawCanvas` 15979：canvas 宽高=原图，CSS 只缩放显示）。所以大图上笔画是精确的，但历史栈是"整幅像素快照 × 40"，大图很吃内存——迁移后改成 Goohai 的 1536 编辑分辨率更省。
- 画布**没有反转**，也没有选框；遮罩的"白色区域=要改的地方"这个极性由 `maskCanvasFromDrawCanvas`（19674）一处决定。
- 擦除入口（工具栏"擦除"）现在复用遮罩画布：画白色区域→送擦除工作流。

好消息：遮罩在画布里已经是一个"独立上传的 PNG 素材"，所以换绘制引擎是**换前置的画图工具**，后面"挂到节点 → 生成时带上"这条路完全不用改。

## 四、迁移方案（技术上怎么落）

1. **新写一个独立模块** `static/js/mask-editor.js`：把 Goohai 那套精简搬过来，只保留绘制能力，去掉 ComfyUI 专有的节点/上传/预览逻辑。
   - 结构：全屏遮罩层 + 顶部工具带 + 左侧输出面板 + 舞台（底图 img + 手绘层 canvas + 选框层 canvas + 笔刷光标）
   - 复用它的成熟算法：填洞 flood fill、选框加减/平移、右键调笔刷、光标锚点缩放、1536 编辑分辨率 + 原尺寸最近邻放大、反转用标志位
   - **唯一要改进的地方**：撤销栈。它的做法是每步存一整张 1536 画布（一步约 9MB，50 步能吃掉几百 MB）。我们改成"步数上限 + 压缩存储"（或只存笔画的增量指令），保证长时间画也不卡、不爆内存。
2. **只接两个接缝**（画布侧唯一入口，改动很小）：
   - 打开：顶栏"遮罩"按钮 → `openMaskEditor(图片URL, 已有遮罩URL, 原图宽高)`
   - 保存：编辑器回传遮罩 PNG → 走现有的"上传素材 + 写回 `node.images[i].mask` + pushUndo + scheduleSave"这条老路
3. **旧代码回收**：删掉弹窗内遮罩模式的工具条（`#imageMaskTools`）、黑白叠加色、`maskTool` 相关分支、`maskCanvasFromDrawCanvas` 之外的旧绘制路径。
4. **"擦除"功能要特别小心**：现在的"擦除"是复用遮罩画布实现的（画白色区域送去擦除）。迁移时二选一：
   - 保留老路径给擦除用（新编辑器只服务"遮罩"）；
   - 或擦除也走新编辑器（多一个"导出为擦除用图"的分支）。
   建议前者：先把遮罩换掉，擦除逻辑不动，风险最小。
5. **批注工具不动**（拆分后它已经是独立入口），下一轮再按同样方式升级。

## 五、需要你拍板的三件事

**决策 1：形态怎么放？**
- A（推荐）：点"遮罩"直接进**全屏编辑器**（就是图2那种专注形态），保存后回画布。弹窗里不再有遮罩模式。
- B：仍然在图片编辑弹窗里画，只把工具带升级。省一次跳转，但弹窗本来就不大，全屏那套工具塞进去会挤，右键调笔刷/快捷键也容易被弹窗吃掉。

**决策 2：颜色叠加 / 多色遮罩要不要？**
这是 Goohai 最花哨的一半：可以画红区、绿区、蓝区，每色能单独当一层，导出成"原图 + 半透明彩色块"的图；也能只导出纯黑白遮罩。
- 要它，得先明确**彩色那张图拿去干什么**：是当参考图喂给图生图（提示"这块改这个、那块改那个"），还是只作为可视化预览？画布现在的生成链路只吃一张黑白 `mask_url`，多色图得走参考图通道，语义要你定。
- 不要它（推荐先不要）：先把画笔/橡皮擦/选框/反转/填洞/撤销这套手感做扎实，颜色叠加留作第二步。

**决策 3：编辑分辨率**
Goohai 在 1536 长边下画（流畅）。代价是超大图上笔迹边缘略糙（保存时放大用最近邻，只会有硬边不会糊）。

画布现在是按原图分辨率直接画：**笔迹更精细，但大图（比如 4K）每画一笔都在全像素上算，撤销还存整幅快照，会明显卡和吃内存**。建议跟 Goohai 一致选 1536——如果某天需要极致精细，可以再放开到原图尺寸。

## 七、风险与坑

1. **坐标对齐**：遮罩必须与图片像素严格对齐，否则重绘错位。缩放/平移只是显示，导出必须回到原图坐标系。
2. **多人协作**：遮罩是节点字段，两人同时画同一张图的遮罩以最后一次保存为准——与现状一致，不做额外锁。
3. **触屏**：右键调笔刷、键盘快捷键在平板上没有，需要降级为滑杆 + 按钮（画布本来有滑杆，保留）。
4. **"擦除"复用**：见第四节第 4 条，这是最容易踩坏的旧功能。
5. **旧画布兼容**：已有 `mask` 素材的图片重开编辑器时要能正确载入（老格式是黑白 PNG，新编辑器按"已画区域"读入即可）。
6. **遮罩只在 GPT-Image-2 上真正生效**：后端只给 GPT-Image-2 把 `mask_url` 当遮罩发给上游 `/images/edits`，其它在线模型会**静默丢掉**遮罩；ComfyUI 工作流里是靠"图片 alpha=255-max(rgb)"反推遮罩。
7. **一个语义疑点（不是本轮的锅，但迁移时该对齐）**：官方 `/images/edits` 用"alpha=0 的区域=要改的地方"，而画布现在导出的是**全不透明的黑白 PNG**。也就是说遮罩在 GPT-Image-2 上不一定真起作用。Goohai 的导出本来就带 alpha，迁移时顺手对齐成"遮罩区透明"，可以一并解决——但这会改变现有行为，需要你点头。
