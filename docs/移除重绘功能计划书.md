## 一、我理解的需求

图片顶部工具条（选中图片后浮在卡片上方那一排）已经有「图片编辑 / 抠图 / 扩图 / 擦除 / 放大 / 遮罩 / 批注 / 角度 / 裁剪 / 宫格切分」十个按钮。这次再增加一个：

**「移除重绘」按钮**，点开一个专门的全屏遮罩编辑页，用途是把不需要的东西抹掉、或者只把某块区域重新画一遍。

具体要求（逐条对齐）：

1. 按钮放在图片顶部工具条里，和「擦除」这类工具同级。
2. 点开后是**全屏遮罩编辑页**，画笔涂抹手感、橡皮擦、选框、撤销/重做、反选、清空、画笔大小、适应窗口、缩放、自动填充漏洞这些**全部复用现有遮罩编辑器**，不重新做一套。
3. 这个页面**不需要「颜色叠加」模式**——整个模式切换那一栏都可以不出现，只有涂抹遮罩这一种用法。
4. 原来右下角（工具条右侧）的**「保存遮罩」按钮改叫「运行」**，点击后直接把当前图 + 涂抹区域送进 ComfyUI 工作流。
5. 页面**底部居中**放一个提示词输入框，对应工作流里的 `#303` 节点；框的**正上方**有一行说明文字：
   > 清空提示词为移除；非空提示词为局部重绘
6. 清空提示词 = 只抹掉涂抹区域（移除）；写了提示词 = 用这段提示词重画涂抹区域（局部重绘）。这个判断不用我们写逻辑，工作流内部自己会切分支（见第二节），我们只要把提示词如实传进去。
7. 运行完成后，结果作为一张新图片出现在画布上（后续再确认落点，见第六节）。

先把上面这套理解做成计划，确认无误后再动代码。

## 二、工作流分析

文件：`workflows/system/Qwen-2.1-移除、局部重绘_Turbo_api.json`（647 行，API 格式，已经是画布可直接跑的结构）

### 2.1 主链路

```
#310 加载图像（LoadImage）
   ├─ IMAGE ─────────────┐
   └─ MASK（取自图片 alpha 通道）
        │
        ├─ #201 / #249 GH_MaskCropV2：按遮罩把要处理的区域裁出来
        │
        ├─【移除分支】
        │    #204 GulfSeaImageMergeMask 把 #205 纯绿(#00ff00)填进遮罩区
        │    → #118 TextEncodeQwenImage21GH（固定提示词「移除图像中的绿色区域」）
        │    → #217 LoRA「Qwen2.1_万物移除Remove_GH」strength 1.0
        │    → #269 / #270 采样
        │    → #212 GH_CropRestore 贴回原图 → 移除结果
        │
        └─【重绘分支】
             #249 裁切结果 → #247 / #250 缩放到 #288 限定的最大采样尺寸
             → #179 QwenImagePromptOptimizer（本机 GGUF 模型，把用户提示词改写得更适合生图）
             → #255 文本编码
             → #258 LoRA「Qwen2.1 一致性无偏移_GH_V1.0」strength 0.48
             → #274 / #275 采样
             → #252 GH_CropRestore 贴回原图 → 重绘结果

#260 GoohaiAnyExists（读 #303 是否为空）
→ #308 ComfySwitchNode：为空取 #212（移除），非空取 #252（重绘）
→ #38 SaveImage
```

### 2.2 我们只碰三个节点

| 节点 | 类 | 字段 | 我们传什么 |
| --- | --- | --- | --- |
| `310` | `LoadImage` | `image` | 上传到 ComfyUI 的文件名（**遮罩已经合成进图片 alpha**） |
| `303` | `PrimitiveStringMultiline` | `value` | 用户输入的提示词（`trim()` 后的原文；空白＝空串） |
| `267` | `RandomNoise` | `noise_seed` | 每次运行随机一个整数，避免同一张图反复出同一个结果 |

其余节点（`118` 固定绿区提示词、`217`/`258` 两个 LoRA、`269`/`270`/`274`/`275` 采样、`288` 最大采样尺寸 2048、`179` 提示词优化）**全部使用工作流里的固定值**，第一版不暴露给界面。

### 2.3 两个必须知道的特性

- **遮罩靠图片 alpha 传递**。工作流的 MASK 输出来自 `#310` LoadImage 的 alpha，所以遮罩不能单独传，必须把「白色涂抹区」做成透明，再上传成一张 RGBA PNG。这个能力画布里已经有了（`comfyNameForMaskedRef()`，`static/js/smart-canvas.js:23476`），「擦除」就是用的它。
- **两个分支都会算**。`308` 只决定最终取哪张图，移除和重绘两条链路都会执行完，所以这个工作流本身比单分支慢；这属于工作流方的设计，我们不拆它。
- `179` 是**本机运行**的提示词优化模型（`Qwen-Image-2.1-PE-I2I.Q5_K_S.gguf` 等），不依赖外部 API；但意味着用户写的提示词会被模型改写一遍，属于预期行为。

## 四、改造方案

### A. 交互

1. `static/smart-canvas.html` 在「擦除」后面加一个按钮：
   ```html
   <button type="button" data-toolbar-kind="image" data-image-toolbar-action="remove-redraw"
           title="移除重绘" data-i18n-title="smart.removeRedraw">
     <i data-lucide="wand-2"></i><span data-i18n="smart.removeRedraw">移除重绘</span>
   </button>
   ```
   图标用 `wand-2`（已确认本地 lucide 包含；`sparkles` / `wand-sparkles` 已被「图片编辑」「指定抠图」占用）。
2. `runImageToolbarAction()` 增加分支，调用新函数 `openRemoveRedrawEditorForImage(node, index)`（放在 `openMaskEditorForImage` 旁边，第 20300 行一带）。
3. 编辑页打开后的形态：
   - 顶部工具条：标题「移除重绘」，左边三工具（画笔/橡皮擦/选框）、画笔大小、撤销/重做/反选/清空，右侧「取消」+「运行」。
   - 右侧面板：**没有模式切换（仅遮罩/颜色叠加那一行）**，直接是「自动填充漏洞」+「适应窗口 / 缩放」。
   - 底部居中：提示词输入框，上方一行说明「清空提示词为移除；非空提示词为局部重绘」。
   - 底部页脚：保留原有的快捷键提示，提示文案改成「涂抹要移除或重绘的区域，点击运行」。
4. 点「运行」：没有涂抹就提示「请先涂抹要处理的区域」并留在页面上；有涂抹就关闭编辑页、在画布上生成一个「正在移除重绘…」的节点跑任务。

### B. 运行链路

```
点「运行」
  → 取出遮罩 PNG（mask-editor 的 buildResult().maskBlob）
  → 判空：192×192 缩略采样有白色才继续（复用 maskBlobHasPaintedArea 的思路）
  → pushUndo()
  → createImageGenerationNode()：放在源图右侧 x+width+200
      title = "正在移除重绘…"，running = true，pending = 1
      runInputRefs = [源图]
      runSettings = {engine:'comfy', comfyMode:'custom', comfyWorkflow: 本工作流, apiKind:'image'}
  → comfyNameForMaskedRef(源图, 遮罩)  →  得到 ComfyUI 侧文件名
  → POST /api/canvas-comfy-tasks
      { workflow_json: 'system/Qwen-2.1-移除、局部重绘_Turbo_api.json',
        params: { '310': {image: 文件名},
                  '303': {value: 提示词.trim()},
                  '267': {noise_seed: 随机整数} },
        type: 'remove-redraw', client_id: smartClientId }
  → 轮询直到 succeeded / failed
  → 成功：live.images = 结果图，title = "移除重绘"，markSmartNodeComplete，addSmartGenerationLog
  → 失败：title = "移除重绘失败"，写 lastRunError，toast 带错误尾部
```

要点：
- 源图用 `imageForDisplay()` 的结果（已裁切/已烘批注），保证「编辑器里看到的」和「送去处理的」是同一张，遮罩尺寸不会错位。
- 结果节点**不建连线**，与「擦除」一致（结果是一张独立成品图，来源记在 `runInputRefs` 和节点元数据里）。
- 上传的临时 blob 用完即 `revokeObjectURL`，不留垃圾。
- 并发保护：同一张图同一时刻只允许一个移除重绘在跑（沿用「擦除」的请求键思路）。

### C. 遮罩编辑器改造（向后兼容，默认行为完全不变）

`static/js/mask-editor.js` 新增两个可选参数，只有新入口会传：

| 参数 | 作用 |
| --- | --- |
| `hideColorMode: true` | 不渲染 `.me-seg` 模式切换，强制 `mode='mask'`；`updatePanel()` 里对应逻辑加保护 |
| `promptBox: { guide, placeholder, value }` | 在 `.me-stage` 底部居中插入 `.me-prompt` 卡片：上方 `.me-prompt-guide` 说明、下方 `textarea.me-prompt-input`；提供 `getPrompt()` 读取当前文本 |

另外一处小修：`save()` 的 catch 里改成优先显示 `error.message`（没有才用原来的 `labels.saveFail`），这样「请先涂抹要处理的区域」这种业务提示能原样弹出来，而不是一句笼统的「保存失败」。

按钮文案不需要改代码：`labels.save` / `labels.saving` 本来就是外部传入，新入口分别传「运行」「运行中…」即可（`setBusy()` 会自动切换）。

`static/css/mask-editor.css` 新增 `.me-prompt` 一组样式：绝对定位 `left:50%; bottom:24px; transform:translateX(-50%)`，宽度约 460px、深色半透明卡片、`textarea` 3 行、说明小字 11px、`:focus` 边框高亮；配色沿用现有 CSS 变量。

### D. 参数映射

不新增 `.config.json`。

理由：`Qwen Image 2.1 扩图` 那种配置文件是给「通用 ComfyUI 工作流节点」做可视化参数表单用的；本次是专用入口，参数直接按节点 id 传（和「擦除」用 `移除-Kontext-api.json` 的方式一致），少一层映射就少一处出错点。若以后想让它在「工作流节点」里也能手动选用，再补 `Qwen-2.1-移除、局部重绘_Turbo_api.config.json`（`310` image、`303` textarea），属于可选二期。

### E. 兼容与边界

- **旧画布**：不新增节点类型，结果节点仍是 `smart-image-generation`；新元数据字段全部有默认值，老画布加载/保存/再加载不受影响。
- **空提示词**：`trim()` 后为空就传空串 → 工作流走移除分支。只输入空格也按空处理。
- **没有遮罩**：不允许运行，提示并留在编辑器。
- **已有遮罩**：打开时不回填旧的遮罩（这是一次性的涂抹），与「擦除」一致；也不会把这次涂抹写回图片的 `mask` 属性（避免污染原图的遮罩/颜色叠加）。
- **失败与超时**：沿用现有 30 分钟窗口与错误透传；节点标记失败、可重试。
- **刷新页面**：运行中的任务不会续跑（与「擦除」「放大」现状一致），属于已知限制，第一版不扩大范围。
- **i18n**：新增词条全部中英双语，放 `static/js/i18n/smart-canvas.js`（`smart.*` 段）：
  `smart.removeRedraw` / `removeRedrawEditorTitle` / `removeRedrawHint` / `removeRedrawNeedMask` /
  `removeRedrawRunning` / `removeRedrawDone` / `removeRedrawFailedTitle` / `removeRedrawFailed` /
  `removeRedrawPromptGuide` / `removeRedrawPromptPlaceholder` / `removeRedrawRun` / `removeRedrawRunningBtn` /
  `removeRedrawResultHint`
- **缓存戳**：按仓库规矩，HTML 的 `?v=` 由服务端维护，不手工批量改写；本次若跟着功能改动需要刷新，只保留功能 hunk。
- **节点显示**：结果节点复用「擦除」的工具结果语义（`node.erase` 元数据，不被当作可再次运行的生成节点），新增 `erase.kind = 'removeRedraw'`，在标题/图标/提示三处按 kind 显示「移除重绘」+ `wand-2`。
