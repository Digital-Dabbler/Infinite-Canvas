# 图片生成节点提示词库布局对齐设计

## 目标

让智能画布图片生成节点的提示词库交互和提示词框布局完全复用文本节点的模式：已应用的预设在文本框内顶部显示，提示词库入口位于右上角，复制入口位于右下角。

## 范围

- 仅修改智能画布前端的提示词组合器与共享预设控件样式、绑定。
- 不修改后端接口、提示词库数据、画布持久化格式或生成请求字段。
- 保持已有图片/视频生成节点、旧画布的 `promptPresets` 数据和上游提示词锁定行为可用。

## 交互与布局

1. 当前图片生成组合器中、位于提示词框外的 `composerPresetControls` 不再显示为独立横条。
2. 组合器将该控件放入 `.prompt-row` 内部，采用文本节点 `.prompt-node-text-wrap` 的内嵌布局：
   - 已选预设显示为可拖拽排序、可移除的标签；
   - 无预设时不占用文本框空间；
   - 标签区域有独立滚动与高度限制，长提示词仍可编辑。
3. 提示词库入口改为文本节点同款右上角图标按钮：
   - 打开现有的全局提示词库；
   - 目标固定为当前图片/视频生成节点；
   - 应用、取消应用、拖拽排序和清空预设继续复用 `prompt-presets.js` 的既有状态逻辑。
4. 文本框右下角继续使用已有复制按钮；复制作者输入文本，最终提交仍由现有组合函数生成“所有前缀 + 作者输入 + 所有后缀”。

## 兼容与错误处理

- 上游提示词节点控制输入时，保持现有不可编辑/不可应用预设的保护和用户提示。
- 提示词库在目标节点已删除或变为不可编辑时，复用现有错误提示，不写入失效目标。
- 不迁移或重写旧画布数据；读取时沿用现有 `promptPresets` 与 `promptPresetTextModelVersion` 兼容逻辑。

## 验证

1. Node.js 检查修改后的 JavaScript 语法。
2. 打开智能画布并选择图片生成节点：检查无预设、单预设和多预设的文本框内布局。
3. 从提示词库应用/取消预设，检查标签、右上角入口和右下角复制按钮。
4. 检查标签拖拽与删除、保存后刷新、旧画布加载、上游提示词锁定和小屏布局。
5. 运行 `git diff --check`，确认最终差异仅限设计与任务文件。
