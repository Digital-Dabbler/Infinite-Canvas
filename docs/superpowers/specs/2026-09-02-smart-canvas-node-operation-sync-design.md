# 智能画布节点操作同步设计

## 目标

将智能画布从“整图快照保存 + 冲突后整图合并”改为节点级操作同步。每张画布彼此隔离；用户操作自动保存；同一画布可并行运行多个生成任务；迟到的旧请求绝不能覆盖新状态或复活已删除节点。

## 范围

本设计覆盖智能画布的节点字段、连线、删除、生成任务状态、结果及协作编辑提示。普通画布不恢复。现有身份、配置组、用量、媒体所有权和异步任务隔离契约必须保持。

## 同步模型

每一个持久化改动提交为一个画布操作，而不是完整 `nodes`、`connections` 和画布状态的快照。操作至少带有画布 ID、客户端 ID、操作 ID、实体 ID、字段/动作和值。

服务端在 `CANVAS_LOCK` 中校验、应用单个操作并生成单调递增的画布修订。成功后，向该画布的订阅者广播已确认的操作和结果修订。客户端只将该操作应用到内存中的目标节点或字段；不因实时消息或轮询重新加载整张画布。

首次打开画布仍获取一份完整快照。此后实时同步只使用操作流；断线重连时按画布修订补取缺失操作，若历史不可用才显式要求重新加载。

## 并发规则

1. 画布是独立同步边界。A 画布的事件绝不触发 B 画布的保存、读取或渲染。
2. 不同节点、不同任务及同一节点的不同字段可并行提交。
3. 对同一节点的同一字段，服务端按接收顺序接受有效操作；最后一个有效操作为最终值，并广播该值。
4. 客户端不等待网络确认才继续编辑或生成。它可乐观显示自身操作，并以服务端确认的字段值收敛。
5. 删除优先。服务端为节点保留删除墓碑；删除修订之后抵达的更新、生成进度、结果或旧保存均拒绝写入，不能复活节点。
6. 撤销恢复是一个新的显式恢复/创建操作，带新节点 ID 或明确的新生代标记，不能由旧更新隐式完成。

## 生成任务

生成提交、排队、进度、完成、失败和取消均通过 `canvas_id + node_id + task_id` 定位。任务完成仅原子更新绑定节点的任务条目、结果、当前预览及日志；不读取后再写回整张画布。

计时以服务端确认的 `started_at`、`finished_at` 为唯一基础。前端两秒交互冷却只影响按钮可用性，不得写入或推断生成完成状态。一个节点可拥有多个并行任务，每个任务独立完成；节点仅在无未完成任务时显示整体完成状态。

## 协作提示（临时 Presence）

实时频道按 `canvas_id` 订阅。用户将焦点放到节点时发送 `node_presence` 心跳，载荷只含画布、节点、当前认证用户的公共显示名与会话实例标识。该状态不写入画布 JSON，不参与版本冲突和撤销。

每个浏览器会话持续更新其当前聚焦节点。其他用户在该节点上看到除自身外的全部编辑者名称与高亮。失焦、离开页面、WebSocket 断开或连续 15 秒未收到心跳时，服务端移除该 presence 并通知该画布订阅者。

## 服务端边界与安全

画布操作、订阅、补取和 presence 全部先验证认证身份及该用户对目标画布的访问权。广播只发送给订阅该画布且有访问权的连接，不能使用当前全局广播再让前端过滤。操作载荷只允许既定节点字段和动作，服务端继续负责路径、媒体、任务、配置组和用量校验。

## 迁移与兼容

旧画布 JSON 继续作为快照存储格式。上线时为既有画布分配当前修订，初始化空操作日志和删除墓碑代次；旧页面的全量 `PUT /api/canvases/{id}` 不再作为日常同步入口，需在兼容期明确拒绝或转换为一次性受控迁移，绝不能继续接受未经字段级约束的全量覆盖。

## 验收与测试

- A、B 两个不同画布同时编辑：A 的实时事件不会引起 B 的请求、保存或渲染。
- 同一画布的两个标签页分别移动不同节点：两项位置均保留。
- 同一节点两个字段并发更新：两个字段均保留；同一字段乱序抵达时以服务端最后有效操作为准。
- 节点删除后，让旧移动、切换预览、生成成功与失败回调依次抵达：节点始终不复活。
- 同一节点并行提交多个生成任务：结果与各自计时正确收敛，按钮冷却不显示“已完成”。
- 两个用户聚焦同一节点：双方均看到对方；第二人离开或断线 15 秒后提示消失。
- 未授权用户不能订阅、读取、操作或接收任意画布的节点事件。
