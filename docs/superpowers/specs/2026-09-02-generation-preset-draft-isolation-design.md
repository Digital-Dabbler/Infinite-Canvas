# 生成节点预设提示词与输入草稿隔离设计

## 目标

生成节点运行、任务恢复或重新选中后，输入框只能显示作者实际输入的草稿；提示词预设的前缀和后缀只能用于最终提示词预览与提交请求，不能回写为可编辑正文。

## 根因

运行元数据同时承担生成记录和编辑草稿恢复的职责。空正文时，运行记录中的最终提示词包含预设内容；后续恢复输入框时若把该记录当作草稿使用，预设文本会被写回输入框。

## 设计

- 保留 `promptDraftHtml` / `promptDraftText` 为唯一可编辑草稿来源，优先于 `runPrompt` 恢复 Composer。
- `runPrompt` / `runModelPrompt` 继续记录本次实际显示与发送的提示词，允许其中包含预设；它们只供历史、预览与复现使用。
- 当运行开始时，元数据中的草稿快照从节点的草稿字段取得，而不是从已经组合预设后的请求提示词派生。
- 对没有草稿字段的旧节点，保留现有 `runPrompt` 回退，避免影响历史画布打开。

## 错误处理与兼容

- 上游提示词节点控制输入时，既有锁定与请求组合规则不变。
- 图片引用 token 的 HTML 草稿继续原样保存与恢复。
- 旧节点没有 `promptDraftHtml` / `promptDraftText` 时，仍可由 `runPrompt` 显示历史提示词。

## 验证

- 空正文、仅预设：运行后重新选中节点，输入框为空，最终预览与请求仍含预设。
- 正文加预设：运行后输入框仅保留正文，最终预览仍为前缀、正文、后缀。
- 含图片提及的草稿在运行后仍恢复为可编辑 token。
- 运行 JavaScript 语法检查、定向静态回归测试及 `git diff --check`。

## 影响范围

修改仅限 `static/js/smart-canvas.js` 的 Composer 草稿恢复与运行快照处理；不变更后端、预设库数据、已有画布结构或配置组权限。
