# 智能画布媒体节点拖放与粘贴替换设计

## 目标

让已有的图片、视频和音频上传节点可以在不打开资源选择器的情况下替换其当前资源：

- 将一个匹配类型的本地文件、可解析的本地路径或媒体 URL 拖放到该上传节点上；
- 选中该上传节点后，从剪贴板粘贴一个匹配类型的媒体文件。

这只是对上传节点的替换入口扩展。现有的资源选择器、文件选择器、画布空白处导入和节点创建语义保持不变。

## 交互规则

### 拖放

1. 当可识别的媒体被拖到已有上传节点时，节点进入替换高亮状态，并显示与目标类型相符的提示，例如“松开以替换图片”。提示文本和图标与高亮边框同时出现，状态不只依赖颜色表达。
2. 放下一个匹配类型的资源后，节点优先处理替换并阻止事件冒泡到画布导入、节点拖动或平移逻辑；使用既有的定向替换路径替换节点的唯一媒体项，保留节点 ID、位置、连线和工作流关系。
3. 拖到画布空白处仍按当前行为创建新的上传节点，不会替换任何已有节点。
4. 拖到图片、视频或音频上传节点但类型不匹配时，拒绝操作并显示说明原因和修复方式的提示，例如“此节点仅支持音频，请拖入一个音频文件”，原资源不变。

### 粘贴

1. 焦点不在输入框或可编辑区域时，若当前选中的是已有媒体的上传节点，粘贴一个匹配类型的剪贴板文件会替换该节点资源。
2. 未选中可替换上传节点时，继续沿用当前粘贴文件后创建上传节点的行为。
3. 节点类型和剪贴板媒体类型不匹配时，不执行替换，也不影响原资源。

### 单资源约束

替换操作只接受一个资源。若一次拖放或粘贴多个文件，显示明确提示并不做替换，避免当前替换 helper 只取首项而造成静默丢失。批量导入到画布空白处的既有行为不变。

### 进行中与完成反馈

1. 用户放下或粘贴有效资源后，节点立即进入上传中状态；上传结束前拒绝新的拖放和粘贴替换请求，防止重复提交或竞态覆盖。
2. 成功后，节点预览在 150–200ms 内以 `opacity`/`transform` 的微过渡更新，并给出简短成功通知。启用 `prefers-reduced-motion` 时取消该过渡。
3. 上传失败时，原资源和节点连接保持不变，通知明确说明失败原因并提供可恢复路径，例如重新拖入、粘贴或使用资源选择器。

## 实现边界

- 在 `static/js/smart-canvas.js` 中为上传节点绑定定向 `dragenter`、`dragover`、`dragleave` 和 `drop` 事件，并复用现有的拖放 payload 解析和上传/导入逻辑；节点处理成功识别的投放后必须阻止冒泡。
- 扩展全局粘贴路由：只在选中且已有媒体、且不处于上传中的上传节点上把单文件操作转换为 `replaceIndex: 0` 的定向替换；其他情况维持原路由。
- 使用既有的 `appendImagesToSmartNode()`、撤销、`render()` 与 `scheduleSave()` 路径，避免引入新的持久化格式或服务端 API。
- 在 `static/css/smart-canvas.css` 增加临时替换高亮、提示和上传中样式，并只用 `opacity`/`transform` 实现可取消的预览过渡；在 `static/js/i18n/smart-canvas.js` 补齐中英文用户文本。
- 将替换状态、成功、类型不符、多文件拒绝和上传失败通过既有或新增的 `aria-live="polite"` 通知区域公布，且不抢走焦点。现有资源选择器与文件选择器继续作为键盘和非拖放替代入口。
- 不修改后端、权限、资源路径、上传接口或生成节点。生成结果节点不作为此次拖放替换目标。

## 错误处理与兼容性

- 没有可识别媒体、媒体类型不匹配、上传进行中或多媒体替换请求均不写入画布状态，并给出包含修复方式的可读提示；多文件消息必须明确“未替换任何资源”。
- 粘贴到文本输入、提示词编辑器等可编辑区域时保持原生行为。
- 空的上传占位节点仍可使用既有上传入口；本功能只将“已有资源的上传节点”识别为替换目标。
- 三类上传节点的持久化类型继续分别为 `smart-image-upload`、`smart-video-upload` 和 `smart-audio-upload`，不增加字段或迁移。

## 验收与验证

1. 在各自已有节点上分别拖入图片、视频、音频，确认资源替换、节点 ID/连线保持且可撤销；确认投放不会创建额外节点或开始节点拖动。
2. 选中各类已有上传节点后粘贴对应剪贴板文件，确认资源替换；未选中节点时确认创建新节点。
3. 对每个节点类型测试不匹配媒体和多文件粘贴/拖放，确认显示原因、修复方式及“未替换任何资源”，且资源不变。
4. 验证上传中状态会阻止重复拖放/粘贴；模拟失败时确认原资源保留并可重试。
5. 以键盘使用资源选择器和文件选择器，确认替代路径仍可用；确认通知通过 `aria-live` 可读且焦点不跳转。
6. 在明暗主题下检查高亮、提示与上传中状态的对比度，确认文字/图标不只依赖颜色；启用减少动态偏好后确认预览切换无动画。
7. 确认空白画布拖放、资源选择器替换、文件选择器替换与可编辑文本框粘贴不回归。
8. 运行 JavaScript 语法检查、国际化完整性检查和 `git diff --check`；如可用，在已登录本地界面进行上述手工验收。
