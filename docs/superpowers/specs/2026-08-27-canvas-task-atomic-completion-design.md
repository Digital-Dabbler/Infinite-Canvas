# 智能画布常规 API 任务原子完成设计

## 目标

修复常规 API 图片/视频生成偶发的“上游和生成日志均成功，但画布节点持续等待”问题。完成结果必须只写入当前有效节点，且不会被画布同步、浏览器刷新、重复轮询或网络重试覆盖或重复追加。

## 范围

本设计仅覆盖创建本地 `canvas_*` 任务的常规 API 图片与视频路径，包括 RunningHub 的模型模式。

不改变下列路径的调度、批次组织或结果写入策略：

- RunningHub 应用和工作流直连模式；
- ComfyUI 运行；
- 智能循环、级联及其预览/输出槽机制。

这些路径只可获得不改变运行语义的旧对象防护；不会被纳入本次服务端结果编排。

## 现状与根因

常规 API 任务由服务端持久化为本地画布任务，浏览器在 `pendingTasks` 中保存任务 ID 并轮询。画布同步合并会替换前端的 `nodes` 数组，但某些完成回调仍持有替换前的节点对象。回调可将成功日志写到当前画布对象，同时将图片和 `pending` 清理写入旧对象；下一次整画布保存于是保留日志、丢失节点完成状态。

服务端目前把整份 `nodes` 和 `logs` 分别保存，因而不能弥补该前端双写竞态。

## 任务绑定模型

每个新建的常规 API 画布任务在提交上游之前，由服务端原子持久化以下不可变绑定：

- `canvas_id`：目标智能画布；
- `node_id`：目标生成节点或循环输出槽；
- `batch_id`：一次用户提交的稳定批次 ID；
- `task_id`：本地 `canvas_*` 任务 ID；
- `submitted_at` 与批次内序号：用于稳定展示顺序；
- 生成日志快照：用于服务端写入一条等价的脱敏生成日志。

节点持久化的任务记录以批次组织。一个节点可有多个并存批次；每个批次含有其精确的本地任务 ID 列表和完成结果。连续提交的结果按提交批次排序，而非按异步完成顺序排序。

## 服务端原子完成

本地任务进入成功终态后，后台任务在 `CANVAS_LOCK` 内执行一次幂等的画布完成操作：

1. 读取任务绑定的画布；若画布不存在或在回收站，标记“未附着”，不修改画布。
2. 查找 `node_id`；若节点不存在，标记“节点缺失”，不复活节点。
3. 确认节点当前仍登记同一个 `task_id` 且属于同一个 `batch_id`；不匹配时标记“绑定失效”，不修改节点。
4. 若该任务已经完成附着，直接返回既有结果，绝不再追加图片、日志或减少计数。
5. 将输出追加到对应批次，按去重规则处理媒体；更新该批次与节点的待处理状态、运行耗时和结果索引。
6. 写入一条成功日志，保存画布并更新版本号。
7. 锁外广播 `canvas_updated`。

任务状态、节点结果、待处理计数和生成日志必须由该单一临界区一起提交。任务查询、刷新恢复或 WebSocket 重试都不得成为第二个画布写入者。

## 前端职责

新版前端提交任务时附带目标画布、节点和批次信息。前端可继续显示本地等待状态、轮询任务状态和恢复连接，但只把服务端画布作为完成结果的事实来源：

- 收到 `canvas_updated` 后拉取并合并服务端画布；
- 错过广播时，沿用元数据轮询和窗口重新聚焦的补拉；
- 不再在 `finalizeSmartPendingTask()` 等轮询回调中追加图片、清理 `pending` 或新增成功日志；
- 对保留的非本地任务路径，完成回调首先按节点 ID 重新定位当前节点，避免写入过期引用。

## 兼容与旧状态

- 新接口只接管携带完整绑定信息的任务。旧页面提交的不带绑定任务继续使用兼容读取路径，避免新旧完成逻辑同时写同一个任务。
- 不需要用户清缓存、关闭页面或手动切换。
- 加载到 `pending > 0` 但无任务 ID 的历史坏状态时，不自动猜测并回填历史图片；停止无限计时，显示“状态不同步”，并提供从对应成功日志恢复结果的显式操作。
- 当前项目的画布对全部登录用户共享。后台完成只检查画布未删除、节点存在、任务绑定仍有效；不增加创建者专属访问规则。任务的原始用户和配置组仍用于上游凭据、用量和任务查询隔离。

## 故障与恢复

服务重启后可恢复查询已有上游任务，不能重新提交可能收费的上游调用。已知上游任务 ID 的本地任务可在查询到终态后走相同原子完成操作；尚未取得上游任务 ID 的任务只标记状态待确认。

每个任务记录脱敏交接审计：本地任务、画布/节点/批次 ID、上游完成时间、画布回写时间及结果（已追加、节点缺失、绑定失效或重试）。不得写入提示词、媒体 URL、密钥或 Cookie。

## 验收与回归测试

自动化测试必须覆盖：

- 在任务完成前触发画布同步/节点列表替换时，两个并发任务各追加一次结果和一条日志；
- 同一节点多批提交按提交顺序展示，较早任务晚完成也不覆盖其它批次；
- 重复终态回调、刷新恢复和网络重试均不重复追加；
- 服务重启后对已知上游任务只查询、不重提，并能完成附着；
- 节点或画布删除后不复活节点；
- 旧无任务 ID 的等待状态停止计时，且仅在用户显式操作时从日志恢复；
- RunningHub 应用/工作流直连、ComfyUI、循环和级联现有测试保持通过。
