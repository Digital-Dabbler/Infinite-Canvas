# 智能画布文本节点传递与运行状态修复设计

## 背景

文本节点当前存在两个相互叠加的回归：仅应用提示词预设且正文为空时，节点输出在组合预设前被判空，导致文本无法传递给下游文本、图片生成和视频生成节点；文本生成请求开始后，面板的焦点保护又会因为生成按钮仍处于焦点中而跳过重绘，导致按钮没有进入生成中状态。

## 目标

- 预设前缀或后缀可以在正文为空时独立组成有效提示词。
- 同一份文本节点输出语义用于文本、图片生成和视频生成下游。
- 点击文本生成按钮后立即显示禁用、加载图标和“生成中”，结束后显示成功或错误状态。
- 保留文本框编辑期间的 DOM 与输入法焦点保护。
- 不修改后端接口、画布持久化格式、配置组权限或已有节点数据。

## 设计

### 统一文本输出

`promptNodePromptItems()` 先判断节点是否存在可组合内容：正文、预设前缀或预设后缀至少有一项即可。未启用拆分时，即使正文为空也调用既有 `promptPresetComposeText()`；启用拆分但正文为空时同样生成一个空正文项，由预设完成最终组合。组合结果继续过滤空字符串。

这样 `promptNodeLLMInputText()`、`textForNode()`、`inputPromptTextFor()` 与 `buildPromptRequest()` 会沿既有调用链获得同一结果，无需为文本、图片和视频分别增加兼容分支。

### 精确的面板焦点保护

`renderTextNodePanel()` 只在焦点位于需要保留编辑状态的输入控件时跳过整块面板重建，例如 textarea、文本输入和正在进行输入法合成的控件。生成按钮、下拉框及其他非文本编辑控件不再阻止重绘。

因此 `runPromptLLMNode()` 设置 `node.running = true` 后的既有 `render()` 会更新按钮；请求完成后的既有 `render()` 会恢复按钮并显示反馈。不会增加第二套手工按钮状态同步逻辑。

## 错误处理

- 正文和预设都为空时，继续显示“需要文本”的既有错误。
- provider 或 model 不可用时，继续使用既有配置错误。
- 请求超时、失败、空响应继续由 `runPromptLLMNode()` 的既有执行令牌和反馈逻辑处理。
- 本次修复不改变上游媒体引用、配置组解析或请求载荷字段。

## 验证

- 仅预设文本可传给下游文本节点并作为 LLM 输入。
- 仅预设文本可成为图片生成与视频生成提示词。
- 正文与预设按前缀、正文、后缀顺序组合。
- 正文和预设均为空时仍被拒绝。
- 点击生成按钮后可观察到运行态，结束后可观察到成功或错误态。
- 文本框聚焦输入及中文输入法组合期间不会因渲染而失焦。
- 运行 JavaScript 语法检查、定向回归测试和 `git diff --check`。

## 影响范围
