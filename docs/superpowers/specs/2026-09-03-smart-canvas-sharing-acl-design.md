# 智能画布公司内分享与协作授权设计

## 目标

智能画布采用公司内默认可查看、可复制，明确邀请后才可编辑的协作模型。授权必须由服务端执行，不能依赖前端禁用按钮。画布之间、画布副本之间，以及它们的实时同步和生成任务必须保持隔离。

## 角色与权限

| 角色 | 获得方式 | 权限 |
| --- | --- | --- |
| 公司内只读成员 | 所有已登录用户 | 查看画布、实时内容变化、节点、素材引用与生成记录；复制整张画布或节点到自己的副本。 |
| 画布编辑者 | 所有者或管理员明确指定 | 包含只读权限；新增、移动、修改、删除节点与连线；管理画布内容；发起该画布的生成。 |
| 画布所有者 | 创建画布、认领未归属旧画布，或由所有者/管理员转移 | 包含编辑权限；邀请或移除编辑者、转移所有权、管理画布共享设置。 |
| 系统管理员 | 系统管理员身份 | 用于治理、恢复与必要的管理操作；不因治理行为取得画布所有权。 |

新画布默认公司内可查看、可复制，只有创建者是所有者和编辑者。任何持链接者可编辑不在本期范围内；未来外部分享须单独设计受控的链接查看能力。

## 持久化与旧数据迁移

每张智能画布新增以下稳定字段：

- `owner_user_id`：所有者的稳定用户 ID；空值表示未归属。
- `editor_user_ids`：稳定用户 ID 去重列表；所有者在判定时天然拥有编辑权，不依赖该列表。
- `ownership_state`：`claimed` 或 `unclaimed`。
- `sharing_version`：授权结构版本，供将来兼容迁移。

新建画布写入当前登录用户为 `owner_user_id`、`editor_user_ids`，并标为 `claimed`。历史画布不根据旧的展示型 `owner` 文本推断账号，统一迁移为 `unclaimed`、空所有者和空编辑者；保留旧展示字段仅作列表兼容，不能参与授权。

任一已登录用户可对未归属画布执行一次性认领。服务端在画布锁中检查当前仍是 `unclaimed`，成功者成为唯一所有者和编辑者；并发认领中只有第一个有效请求成功。管理员可以治理未归属或已归属画布，但自身不会被写为所有者或编辑者，除非明确指定。

## 服务端授权边界

新增单一画布授权 helper，基于认证用户和画布记录返回 `viewer`、`editor`、`owner` 或 `admin`。管理员权限仅在明确管理操作中使用，常规协作逻辑不会把管理员转换成所有者。

- `viewer`：读取画布、列表、元数据、媒体指纹、导出和复制；可订阅内容同步。
- `editor` 以上：节点操作、旧保存兼容入口、连线、日志、设置、封面、回收站内容管理、Photoshop 写入和画布生成任务。
- `owner`：编辑者名单、所有权转移与共享设置。
- `admin`：以上治理操作的受控替代入口，以及恢复/治理所需管理操作；不改变所有权。

所有画布路由、画布绑定的生成/Photoshop 路由、任务恢复、以及 WebSocket `canvas_subscribe` / `canvas_presence` 必须使用同一个 helper。订阅只对可查看者开放；编辑状态仅发送给具有编辑权的订阅者。生成入口服务端再次验证编辑权，不能仅信任已加载画布或前端状态。

管理员的日常会话先按其普通画布身份判定：未受邀时为只读成员，被邀请后为编辑者，拥有画布时为所有者。仅在用户显式进入治理模式后，管理员才使用管理替代权限；治理模式不会写入管理员为所有者或编辑者，退出后恢复普通协作视图。这使管理员能真实测试各协作角色，同时保留必要治理能力。

## 操作、实时同步与副本隔离

现有节点级 operation 协议继续以 `canvas_id` 为唯一同步范围。授权失败不会写入操作日志、不会广播、不会改变任务状态。删除墓碑和“同字段服务端最后有效操作获胜”的规则保持不变。

复制接口在服务端从可查看源画布建立新记录：生成新画布与节点/连线 ID，清除 operation history、删除墓碑、运行态、待处理任务、任务绑定和协作名单；新副本归复制者所有。素材 URL 可作为引用复制，但副本的节点操作、WebSocket 房间、生成任务与日志均仅使用新 `canvas_id`。

## 用户界面

画布列表卡片显示当前用户权限与“待认领”状态，均以图标加文字徽标呈现，不能只依赖颜色。待认领画布为已登录用户提供“认领”；所有画布提供“复制”。

智能画布的只读状态显示固定、不遮挡画布内容的说明：当前仅可查看，可复制整张画布或选中节点到自己的画布继续使用。编辑控件不作为安全边界，但会禁用或替换为复制入口，并在任何被拒绝写入时显示一致提示及可执行的复制操作，而不是暴露 HTTP 错误。

所有者的协作面板使用右侧抽屉，可搜索并添加/移除编辑者、转移所有权。管理员默认看到普通协作视图，只有主动进入治理模式才可代为指定所有者和编辑者；界面明确说明治理不会使管理员成为所有者。转移所有权必须二次确认，明确目标用户和后果，并默认提供“保留原所有者为编辑者”；移除最后一名编辑者、移除自己和认领失败均需显示就近的解释与恢复路径。

只读用户复制选中节点时，先进入跨画布剪贴板，再引导其选择自己可编辑的目标画布；没有目标画布时直接新建副本。该流程不得暗示节点会写回原画布。交互控件必须提供文字标签或 `aria-label`、可见键盘焦点、就地错误和提交中反馈；现有语义色 token 与 Lucide 图标继续作为唯一视觉系统。

## 验收与测试

1. 新画布仅创建者可编辑和发起生成，其他已登录用户可读取和复制。
2. 所有者邀请后，受邀用户可写入；移除后，操作、生成和 Photoshop 写入均返回 403。
3. 历史画布迁移为待认领；并发认领只产生一个所有者；管理员治理不改变自身所有权。
4. 复制产生新画布 ID、新节点/连线 ID，且源/副本操作、任务、WebSocket 广播互不影响。
5. 所有者转移后旧所有者不再管理共享；管理员仍可治理。
6. 管理员在普通视图按自身画布身份受限；显式进入治理模式后可执行治理，且不会被写为所有者或编辑者。
7. WebSocket 只允许合法订阅；只读者不接收编辑占用提示；编辑者可正常看到其他编辑者的节点占用。
8. 完成 Python 语法、智能画布/任务隔离测试、授权定向测试和关键浏览器流程验证。
