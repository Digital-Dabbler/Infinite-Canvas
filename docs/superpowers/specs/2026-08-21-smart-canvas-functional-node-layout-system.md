# 智能画布功能节点统一布局系统

## 背景

现有图片上传、图片生成和视频生成节点分别计算卡片尺寸、媒体预览和结果附属区。部分缩放流程只更新外框或部分媒体元素，导致预览不能随卡片同步；视频内部预览还会绕过生成节点的展示规则而被默认 `cover` 裁切。结果缩略图与视频尾帧的配对也依赖不稳定的 URL 比较，因而可能脱离对应视频或继承不应出现的播放控件。

这份规格将此前“单一预览框 + 独立结果队列”的局部约定扩展到所有功能节点。目标不是统一视觉外观，而是建立一份共享的几何和操作层契约，并在其上保留各节点既有的内容表达与交互。

## 范围与不变量

### 覆盖的功能节点

1. 媒体来源节点：`smart-image-upload`、`smart-video-upload`、`smart-audio-upload`。
2. 生成节点：`smart-image-generation`、`smart-video-generation`，包括多结果、翻页与视频尾帧。
3. 文本与控制节点：`smart-prompt`、`smart-loop`。
4. 运行时的待生成、排队、失败和加载状态，沿用对应节点的同一外框契约。

`smart-workflow-group`、旧兼容分组和 `smart-note` 不是功能节点；它们只复用通用的外框缩放和层级规则，不套用媒体视口或结果队列。

### 必须保留的设计约定

- 节点类型、画布 JSON 字段、生成接口、`images[]` / `activeImageIndex`、连线语义和持久化兼容保持不变。
- 媒体上传节点继续保留资源标题/文件信息；图片、视频、音频保持各自的内容表达。
- 生成节点继续是“主预览在上、结果缩略图队列在下”的层级；结果队列不是主预览的留白，也不作为缩放柄的容器。
- 视频主预览保留点击播放入口；静态尾帧、普通静态缩略图不显示播放入口。
- 既有的拖动、选择、连线、删除、结果切换、双击编辑、替换上传和智能组织交互不得改变。

## 共享布局契约

每个功能节点通过一个纯计算布局对象派生其视觉与交互几何，而不是由 JS、DOM 和 CSS 各自猜测尺寸。布局对象至少包含：

| 字段 | 含义 |
| --- | --- |
| `outerWidth` / `outerHeight` | 节点完整可点击、可选择、可连线的持久化外框。 |
| `contentViewport` | 主体内容的宽高与裁剪边界；媒体、文本或控制内容只能在其中布局。 |
| `accessoryBands` | 标题/文件信息、结果缩略图、状态提示等节点特有的附属区域；显式参与完整高度计算。 |
| `resizeAnchor` | 始终位于主体视口右下角的操作层锚点；不通过额外空白占位。 |
| `connectionY` | 由完整外框计算的连线端口中心；渲染、拖拽和 SVG 连线共用。 |

节点 `w/h` 始终表示 `outerWidth/outerHeight`。缩放手势先更新这两个值，再用同一布局对象同步更新外框、主体视口、附属区、操作杆和连接点。任何媒体元素不得通过固定内联宽高或独立 CSS 尺寸绕过此流程。

## 节点适配规则

### 图片上传

- 主图填充 `contentViewport`，保留完整可见优先的展示策略和已有圆角/边框。
- 缩放时图片包装层与图片元素都读取同一视口宽高；卡片扩大时不得遗留白色空栏，卡片缩小时不得超出边界。

### 视频上传与视频生成

- 主预览使用完整可见优先的 `contain`，并以统一深色背景承接比例差，不裁掉人物或画面边缘。
- 视频播放按钮只属于主视频预览；激活后原有的内联播放替换流程继续工作。
- 视频缩略图可维持静态预览。返回尾帧按规范化媒体身份关联到其所属视频缩略图的正下方；尾帧是静态媒体，不生成播放按钮或激活视频行为。

### 音频上传

- 音频维持紧凑的播放器/文件信息设计，不强行拉成图片比例。
- 外框、最小尺寸、缩放柄、连线锚点和选择层使用共享契约；播放器在 `contentViewport` 内自适应。

### 图片与视频生成结果

- 一个当前结果只渲染一个主预览框，不再出现结果数量造成的叠层底板或偏移边框。
- 主预览是唯一媒体裁剪、圆角和操作层容器；缩放柄覆盖其右下角。
- 结果缩略图队列是独立的底部附属区，完整高度计入节点外框；多结果、尾帧、排队和失败覆盖层均不得改变这个边界关系。

### 提示词与循环

- 文本/控制内容以 `contentViewport` 为可用空间，并保留现有输入、分栏、复制、运行状态和最小尺寸。
- 缩放柄、外框、端口和选择层走共享规则；不将媒体裁切或缩略图规则套入这些节点。

## DOM 与样式边界

1. 所有功能节点使用一致的“外框 → 内容视口 → 附属区 → 操作层”结构与 class 语义。
2. 媒体元素只从其父视口继承 `width:100%; height:100%`；对象适配由节点适配器给出，禁止额外选择器覆盖为与该节点冲突的 `object-fit`。
3. 操作层使用绝对定位并限于主内容视口；缩略图、信息行和文本区域不会为它增加额外高度。
4. 结果缩略图的媒体渲染明确区分 `interactive-video`、`static-video-thumbnail` 与 `static-tail-frame`，避免由通用视频模板隐式带入播放按钮。

## 实施步骤

1. 建立共享布局计算和 DOM 视口助手，迁移外框、端口、缩放即时更新与渲染路径到该助手。
2. 将媒体来源和生成节点接入各自的适配器，移除覆盖主视口的硬编码尺寸与冲突的 `object-fit` 规则。
3. 以规范化媒体身份建立视频与尾帧配对，显式使用静态尾帧缩略图渲染路径。
4. 将提示词、循环节点接入共享外框/操作层契约，同时保留其现有内容结构。
5. 不修改非功能容器的媒体逻辑，只验证它们与通用缩放、选择和端口层仍兼容。

## 验收清单

1. 对每一种功能节点横向和纵向缩放，外框、内容视口和右下角缩放柄始终同步；无白边错位、溢出、裁切或为操作杆预留的空白条。
2. 图片完整受卡片边界约束；视频主预览完整可见且可播放，不发生默认 `cover` 裁切。
3. 图片/视频多结果保留一张主预览和底部结果队列；尾帧只出现在所属视频缩略图正下方，且无播放按钮。
4. 音频、提示词和循环节点在缩放、选择、连接、保存重载后保持现有内容和交互。
5. 缩放后的端口和连接线仍锚定节点完整外框中点；拖动、替换上传、删除、结果切换和自动整理正常。
6. 运行 JS 语法检查、智能画布定向测试、差异检查；如有已登录浏览器会话，逐节点完成实际缩放与结果队列回归。
