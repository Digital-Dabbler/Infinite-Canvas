# 智能画布耐久保存与损坏恢复设计

## 目标

避免画布 JSON 在进程中断时被半写入覆盖；当已有画布损坏时，停止客户端无限重试并给出可恢复的错误。

## 范围与不变量

- 保持 `canvas_id` 隔离、既有授权、节点操作幂等、修订号和 WebSocket 广播行为。
- 不将损坏画布静默重置为空，也不改变其他画布或运行时数据。
- 仅把已解析并持久化成功的快照作为正式文件；临时文件与备份不可作为画布列表或操作目标。

## 设计

### 服务端

`save_canvas` 先将完整 JSON 写入画布目录中的唯一临时文件，刷新 Python 缓冲区并 `fsync`，随后通过 `os.replace` 原子替换正式文件。替换前的完整正式文件保留为同目录 `.bak`，以便人工恢复。临时文件写入或替换失败时，正式文件不变并向调用方报错。

`load_canvas` 捕获 `JSONDecodeError`，返回稳定的 `409` 及机器可判定的 `detail.code = "canvas_corrupted"`。该响应不带文件内容、路径或异常栈，并且不执行操作、授权副作用或广播。

### 客户端

节点操作保存读出失败响应后，若响应表示 `canvas_corrupted`，停止当前画布的自动保存计时器、保留内存改动、显示一次可读提示，不再安排 800ms 重试。其他网络错误和非恢复性失败继续保持现有延迟重试，避免正常离线编辑丢失。

### 既有损坏画布

先复制损坏原件为时间戳 `.corrupt-*.json`。由于文件在一个对象字段后截断，恢复工具只从末尾删除未完成字段并依据 JSON 容器层级补齐关闭符号；恢复后的文件须由 Python JSON 解析成功后，才经原子替换成为正式快照。截断点之后未完整写入的数据不会被伪造。

## 验证

- 单元测试原子保存后正式 JSON 可读取，且临时文件不被保留。
- 人为损坏画布时，`GET` 与操作请求返回 409/`canvas_corrupted`，不返回 500。
- 前端收到该错误后不再创建下一次 800ms 保存重试。
- 已恢复画布能加载，且节点操作仍按原画布 ID 写入和广播。
