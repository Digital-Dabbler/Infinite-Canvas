# 智能画布生成结果预览框设计

## 背景与目标

图片/视频生成节点在有多个结果时，当前主预览、叠层装饰、缩略图队列与节点级缩放柄共享了不清晰的边界：主预览可能视觉越出卡片，重复的叠层边框会干扰层级判断，缩放柄又会随整个节点落到缩略图行下方。

本次采用已确认的“单一预览框 + 独立结果队列”方向：主预览只属于一张卡片，缩略图只属于其下方的结果队列，缩放柄只覆盖主预览卡右下角。

## 视觉与结构契约

1. 每个已有结果的生成节点只渲染一个主预览框；不再绘制结果数量造成的叠卡底板或偏移边框。
2. 主预览框是媒体的裁剪边界：它拥有稳定圆角、`overflow: hidden` 与与媒体一致的宽高，图片或视频不能越过该框。
3. 缩略图队列保持在主预览框下方，是独立的、左对齐的结果选择行；它不是第二张卡，也不承担主预览的边界或缩放操作。
4. 缩放柄只在主预览框右下角叠加显示，使用现有对角缩放语义；它不位于缩略图下方，不为自身占用空白栏，也不遮挡缩略图。
5. 节点的逻辑尺寸仍覆盖“主预览框 + 队列”，以保证拖拽、选择、连线、自动整理和最小地图使用完整节点边界。

## 交互规则

- 点击缩略图、结果翻页、视频尾帧选择和双击预览的行为保持现状。
- 拖动主预览框的非控件区域仍移动节点；缩放柄继续阻止拖拽并走当前节点缩放路径。
- 缩略图行不因缩放柄位置变化而被遮挡，窄节点下仍可横向滚动选择结果。
- 生成、追加、恢复轮询或删除结果时，主预览和队列都从同一 `images[]` / `activeImageIndex` 状态重新计算；不新增持久化字段或接口。

## 实现范围

- `static/js/smart-canvas.js`
  - 移除多结果预览的叠层装饰 DOM 与为该装饰预留的尺寸偏移。
  - 在主预览框内输出生成节点的缩放柄，外层节点不再重复输出该柄。
  - 维持 `generationResultAccessoryHeight()` 与 `generationImageLayout()` 对“预览 + 队列”完整高度的共同尺寸契约。
- `static/css/smart-canvas.css`
  - 将主预览框定义为唯一的裁剪、圆角与边框容器；其内容严格受限于容器。
  - 保持结果队列在预览框下方的独立布局，并仅对生成节点的缩放柄使用主预览框定位上下文。

不修改服务端、画布 JSON schema、生成请求、结果数据结构、缩略图选择逻辑、连接端口语义或其他节点类型。

## 验收与验证

1. 多结果图片节点只出现一张主预览卡，主图四边均在圆角边界内，无重叠卡片轮廓。
2. 缩略图行在主预览下方完整可见，选中态与切换结果正常。
3. 缩放柄显示在主预览右下角，缩放后仍不移动到缩略图下方，也不覆盖缩略图。
4. 节点端口、拖动、缩放、连接线锚点及自动整理仍基于完整节点高度正常工作。
5. 删除当前结果、生成追加结果及视频尾帧结果后，布局不会出现裁切、溢出或重复边框。
6. 运行 `node --check static/js/smart-canvas.js`、相关智能画布测试与 `git diff --check`；若本地已登录会话可用，再进行浏览器实测。
