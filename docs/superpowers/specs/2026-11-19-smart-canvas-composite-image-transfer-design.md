# 智能画布图片加工层综合传递设计（C+ 方案）

日期：2026-11-19
状态：已确认，实施中
关联问题：图片同时经过多种加工（裁切+色块、批注+色块等）后，向下游生成节点只传递了其中一种结果，与预览不一致。

## 1. 问题与根因

用户场景：上传节点先裁切、再涂色块，预览显示"裁切+色块"，但下游生成节点拿到的图只有裁切、没有色块（缩略图与实际生成输入都不带色块）。

根因（`static/js/smart-canvas.js`）：

- 加工结果各存各的文件：原图 `url`、批注成品 `annotation`、裁切成品 `crop.result`、色块成品 `maskColor`、笔迹层 `maskPaint`/`annotationPaint`、黑白遮罩 `mask`。
- 向下传递时按写死的优先级"四选一"（`promptRequestRefs`，约 :24725）：`crop.result` > `annotation` > `maskColor` > 原图。裁切+色块 → 只传裁切；批注+色块 → 只传批注。
- 保存色块时从不回写 `crop.result`（`saveMaskEditorResult`，约 :22544）；保存裁切时也不把色块烘焙进 `crop.result`（`saveCropEditorResult`，约 :22207）——两种操作顺序都丢。
- 预览渲染（`singleMediaHtml` :11084 / `thumbMediaHtml` :10997）的分支顺序与传递不同（色块层优先），所以预览看起来是对的，传递是错的。
- 批注保存后会刷新 `crop.result`（`refreshCropResultForImage` :22156）但从不刷新 `maskColor`，色块成品图会过期。

## 2. 方案总设计（C+）

核心：加工层（批注/裁切/色块）保持分开存，但**预览和向下传递都改成从同一份"层清单"现算**。预览按层清单在屏幕上叠出来；传递时若只有一层就直接用现有文件（零开销），两层以上才现场拼成一张临时图、用完回收。

六个设计决定：

1. **层清单是唯一事实源**。新增函数把一张图的 `url/批注/裁切/色块` 整理成有序层列表，预览渲染器和传递合成器都只认它，不再各写各的规则。
2. **"后画的在上面"**。批注保存、色块保存时各记编辑时间戳（`annotationEditedAt`/`maskEditedAt`），层按时间排序叠放；旧画布没有时间戳，按现有顺序（批注在下、色块在上）兜底，行为不变。裁切是几何操作，永远最后做。
3. **色块合成用"纯色块笔迹+透明度"现拼，不用现成的色块效果图**（`maskPaint` + `maskOpacity`，不依赖 `maskColor`）。`maskColor` 会过期（批注+色块共存时它是旧的），笔迹层永远可以重放。
4. **黑白遮罩通道（`mask`）原样保留**，不进合成图。局部重绘类工作流靠它进 alpha 通道（ComfyUI `comfyNameForMaskedRef` :25653 现成先例、online-image 的 `mask_url`），本次不动。
5. **裁切坐标系机制不动**。色块/遮罩仍活在裁切坐标系里（沿用 `remapMaskForCrop` :22077 搬家逻辑），合成器负责反算回全帧再裁——两种操作顺序结果一致。
6. **临时图回收**：现场合成的图走带"临时"标记的上传，文件名前缀 `tmp_`；服务端定期清扫超过 24 小时的临时文件。每次"编辑"不新增任何文件（与今天相同），只有"多层图参与生成"时多一张临时图。

## 4. 实施顺序（4 个 commit，各自可独立回滚）

1. 层清单 + 合成器 + 传递改造（修掉 bug 本体）
2. 三处预览改同源（兑现"所见即所传"）
3. 后画在上时间戳 + 编辑器底图
4. 服务端临时上传标记 + 清扫 + 导出/另存拉平

## 5. 验收清单

- 先裁后涂 / 先涂后裁：下游图 1 缩略图和实际生成输入都带色块
- 批注+色块共存：合成图两者都有，后画的盖在上面
- 清掉某一层：下游跟着变
- 旧画布打开、生成、保存、重载一切如常
- 单层图（只裁切或只色块）生成速度无感变化

## 6. 风险

- **暂停超 24 小时的任务恢复**：临时合成图可能已被清扫，恢复失败。缓解：提交任务时刷新临时文件时间戳 + 阈值可调。需实测。
- 4K 大图多层合成每次生成多 0.3~2 秒，相对生成耗时（几十秒）无感。
- **行为变化**：过去"裁切+色块"只把裁切图喂给模型，现在带色块——正是本次修复目标，但依赖旧行为出图的流程结果会变。
- 前端改动集中在 3 万行大文件，commit 1、2 是主要回归面，靠分 commit + 验收清单控制。
