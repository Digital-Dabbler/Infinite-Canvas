# 提示词预览配方布局设计

## 目标

将提示词库的“提示词预览”改造成清晰、可扫描的配方视图：用户能先看封面和预设定位，再按顺序理解“前缀 → 用户提示词 → 后缀”，并在不滚动回顶部或底部的情况下复制或应用该预设。

## 范围

- 仅修改 `static/js/prompt-library.js` 的预览 HTML 结构，以及 `static/css/prompt-library.css` 的预览局部样式。
- 保持现有提示词库加载、收藏、应用/取消应用、复制、焦点恢复和 Escape 关闭逻辑。
- 不修改后端接口、提示词库数据结构、画布持久化格式、生成请求或其他库界面。

## 视觉与布局

1. 桌面端预览弹窗为两栏“提示词配方”布局：左栏展示 16:9 封面，右栏展示分类、名称、说明和配方内容；封面使用 `object-fit: cover`，不再留下图片右侧空白。
2. 右栏中的提示词分成三个语义区段：前缀、居中的“用户提示词”占位段、后缀。前缀和后缀为可换行的等宽文本块，组合顺序由配方轨道和标签明确表达，而不依赖颜色。
3. 弹窗使用独立的标题栏、可滚动内容区和固定底部操作区。关闭、复制组合、应用/取消应用在内容较长时仍保持可见。
4. 延续提示词库现有的深灰表面、灰色边界和荧光绿主操作色；不新增外部字体或素材。类型层级固定为分类标签、标题、说明、区段标签、等宽正文五级。
5. 小于 760px 时切换为单栏：封面置顶，操作区仍保留在底部；文本块不产生横向滚动。

## 交互与无障碍

- 对话框以 `aria-labelledby` 和 `aria-describedby` 关联标题和说明；封面保留预设名称作为替代文本。
- 保持图标关闭按钮的可访问名称、键盘焦点环、焦点陷阱和 Escape 关闭；关闭后焦点回到触发“预览”的按钮。
- 复制和应用完成后继续使用既有 toast 反馈；“已应用”状态同时通过文字和图标表达。
- 入场、悬停和按钮反馈仅使用 opacity/transform，时长控制在 150–220ms，并为 `prefers-reduced-motion` 关闭非必要动效。

## 实现边界

- `detailHtml()` 输出新的语义分区和操作栏容器，但继续使用现有 `data-pl-copy` 与 `data-pl-apply` 事件契约。
- 只在 `.prompt-library-preview-*`、`.prompt-detail-*` 等预览作用域内定义样式，避免影响提示词卡片、编辑页和其他资源库。
- 使用局部 CSS 变量统一预览表面、边框、文本与强调色，避免跨页面的全局颜色覆盖。

## 验证

1. 运行 `node --check static/js/prompt-library.js` 和 `git diff --check`。
2. 在桌面端检查有封面、无封面、长前后缀、已应用和未应用状态；确认封面无空白扩展、内容分组清晰、操作区固定。
3. 检查键盘 Tab 循环、Escape 关闭、关闭后的焦点恢复、复制与应用反馈。
4. 在约 375px、768px、1024px 和 1440px 宽度检查单栏/双栏切换、无水平滚动和文本可读性。
5. 检查减少动态效果偏好下的弹窗和按钮状态，并确认现有提示词库和画布使用流程未受影响。
