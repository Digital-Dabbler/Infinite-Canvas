# 文本节点改造计划

日期：2026-08-10
状态：已确认，待实施
范围：智能画布 `smart-prompt` 节点

## 1. 目标

将现有“提示词节点”改造成输出优先的“文本节点”：

- 可直接编辑并输出文本。
- 可使用已配置的文本/视觉语言模型生成文本。
- 可接收上游图片和上游文本节点作为模型输入上下文。
- 下游始终读取节点上方文本框中的可见内容，不再存在隐藏的最终拼接文本。
- 选中节点时显示简洁、与图片生成节点一致的生成面板；未选中时保持为干净的文本框。

节点在创建菜单和可见标签中使用“文本”，底层 `type` 继续使用 `smart-prompt`，避免破坏现有画布、连线和工作流兼容性。

## 2. 已确认的产品规则

### 2.1 输出是唯一真相

`node.text` 是文本节点唯一的输出来源：

- 模型生成成功后，将结果写回 `node.text`。
- 用户双击文本框后可以直接编辑 `node.text`。
- 文本、图片和视频生成节点从上游读取的都是 `node.text`。
- 请求失败、取消或模型不可用时，不得覆盖已有 `node.text`。

原有“提示词预设 + 最终发送提示词”的隐藏拼接模式不再用于下游传递。

### 2.2 上游输入轨道

选中节点后，生成面板顶部显示统一的“输入轨道”，不再单独称为图片区。

输入轨道可包含：

- 图片缩略图：作为视觉语言模型的参考素材发送，不拼入请求文本。
- 文本缩略图：表示上游文本节点的当前 `node.text`，作为请求上下文。

输入轨道从左到右的顺序即文本上下文的合并顺序。最终请求文本为：

```text
上游文本 1

上游文本 2

本节点生成要求
```

图片与文本缩略图混排展示，但只有文本缩略图参与以上文本拼接。

### 2.3 上游文本代替系统提示词

不在默认界面暴露系统提示词、角色设定或高级模型参数。

用户可通过多个上游文本节点组织角色、背景、输出格式、写作风格和约束，并按输入轨道顺序合并。这使上下文来源在画布中可见、可连接、可复用和可调整。

### 2.4 模型范围

模型选择仅包含两级：

1. 模型平台：已启用且配置了 `chat_models` 的平台。
2. 文本模型：该平台已配置的 `chat_models`。

不显示图片、视频或音频生成模型。

视觉语言模型仍属于文本模型：当接入图片时，若当前模型支持视觉输入，则图片随请求发送。模型能力可用名称规则作为兼容回退；后续可扩展为明确的模型能力元数据。

### 2.5 提示词库

生成面板保留“提示词库”入口。

选择提示词库内容后，应写入或追加到“生成要求”输入框，而不是在节点输出之外创建隐藏预设、chips 或最终预览。用户看到的生成要求即实际发送给模型的本节点部分。

## 3. 交互与布局

### 3.1 未选中状态

未选中时节点是简洁的文本输出框：

```text
输入 ○  ┌──────────────────────────┐  ○ 输出
        │ 双击开始编辑文本…         │
        │                          │
        │        当前文本输出        │
        └──────────────────────────┘
```

- 单击节点：选中节点并打开生成面板。
- 双击文本框：进入文本编辑，焦点直接进入文本框。
- 文本框以可阅读预览为主，长文本在节点内滚动。
- 节点仍保留标准输入/输出端口和缩放行为。

### 3.2 选中状态

选中后，节点上方仍是输出文本框，节点下方锚定一个生成面板：

```text
┌────────────────────────────────────────────┐
│ [图片 1] [文本 1] [文本 2]                  │
│                                              │
│ 生成要求                                    │
│ 描述想生成的文本内容…                        │
│                                              │
│ [模型平台 ▾] [文本模型 ▾] [提示词库]  [生成 ↑] │
└────────────────────────────────────────────┘
```

布局顺序固定为：

1. 输入轨道。
2. 生成要求。
3. 模型平台、文本模型、提示词库和生成按钮。

无输入时，输入轨道整行不占空间。

### 3.3 输入轨道细节

- 图片卡片使用现有图片生成节点的缩略图语言。
- 文本卡片使用文档/文本图标、节点名称和顺序编号，例如“文本 1”。
- 文本卡片悬停、聚焦或通过键盘操作时展示内容摘要。
- 文本卡片支持左右拖拽排序；排序结果决定请求文本合并顺序。
- 除拖拽外，必须提供可键盘访问的“左移/右移”操作。
- 在小屏上输入轨道可横向滚动，卡片不压缩到不可辨认。

### 3.4 生成要求

- 字段必须显示可见标签“生成要求”，不能只依赖 placeholder。
- placeholder 使用“描述想生成的文本内容…”作为示例。
- `Ctrl/⌘ + Enter` 触发生成；`Shift + Enter` 换行。
- 生成要求自动保存到节点字段；选中其他节点再返回时保持内容。

### 3.5 状态反馈

- 生成中：生成按钮禁用，显示加载图标和“生成中”；保持现有输出文本可见。
- 成功：写入输出文本框，按钮短暂显示成功状态，并使用简短 toast。
- 失败：错误显示在生成要求下方，明确说明原因和恢复动作；例如“当前模型不支持图片输入，请选择视觉语言模型”。
- 无平台或无模型：对应下拉禁用，并给出“前往 API 设置”的明确提示。

## 4. 视觉规范

### 4.1 设计方向

文本节点的视觉重点是“输出文档 + 输入轨道”，而不是多层设置卡片：

- 上方文本框是稳定的输出文档面。
- 下方生成面板是短暂出现的指令坞。
- 输入轨道的编号真实表达合并顺序，作为本组件的核心视觉签名。

### 4.2 主题与层级

继续使用智能画布现有主题变量和本地 Lucide 图标：

- 输出文本框与生成要求使用不同的边框和背景层级。
- 绿色仅用于“生成”、完成和当前主要动作。
- 图片输入和文本输入除颜色外还使用不同图标与结构，避免只靠颜色区分。
- 不新增在线字体或新的全局主题。
- 输出文本使用现有 `ui-monospace` 风格；界面控件使用项目现有 UI 字体。

### 4.3 尺寸与响应式

- 桌面生成面板宽度与现有 Composer 体系一致，避免超过可视画布。
- 小屏时，模型平台和文本模型保持可读；提示词库可收缩为带 `aria-label` 的图标按钮。
- 生成按钮在触摸设备上最小可点击尺寸为 44px。
- 长错误、长模型名称和长文本不得造成水平溢出。

## 5. 数据模型与兼容

### 5.1 保留字段

保留现有字段以兼容已保存画布：

- `text`
- `promptPresets`
- `promptSeparator`
- `promptSplitEnabled`
- `llmProvider`
- `llmModel`
- `llmInstruction`
- `llmSystemEnabled`
- `llmSystemPrompt`

### 5.2 新语义与建议字段

逐步引入或复用以下语义：

- `text`：唯一输出文本。
- `llmInstruction`：生成要求。
- `llmProvider` / `llmModel`：底部两级模型选择。
- `inputNodeIds` 或现有连线顺序：输入轨道顺序来源。
- `inputOrder`：如现有连线顺序不足以稳定表达用户排序，则新增为节点级 ID 数组。

`llmEnabled` 不再表示是否显示复杂表单；可保留为兼容字段或迁移为运行能力状态。

### 5.3 旧节点迁移

旧 `smart-prompt` 节点加载时：

1. 保留原始 `text` 和模型选择。
2. 将旧 `llmInstruction` 映射为“生成要求”。
3. 保留原始预设数据用于兼容读取。
4. 对下游传递改为显式 `text`，不再在读取时隐藏拼接预设。
5. 如需严格保留旧的最终拼接结果，应在首次迁移时将旧最终结果写入 `text`，并记录一次性迁移标记，避免重复拼接。

迁移后必须完成保存、刷新、重新打开测试，确认节点 ID、连线和输出未丢失。

## 6. 实施步骤

### 阶段一：输出与数据语义

- 重构 `promptNodePromptItems()`，使其默认只返回 `node.text`，拆分输出功能仅在用户显式启用时生效。
- 明确文本节点下游传递、级联运行和工作流导出读取同一输出字段。
- 增加旧节点迁移与兼容测试数据。

### 阶段二：节点本体

- 重写 `promptNodeBodyHtml()` 为简洁输出文本框。
- 实现单击选中、双击编辑、编辑完成后保存和撤销。
- 保留端口、节点缩放、组内紧凑显示与画布拖拽逻辑。

### 阶段三：文本生成面板

- 新建独立的文本生成面板，不复用图片/视频 Composer 的图片参数部分。
- 复用已有 `chatApiProviders()`、`providerChatModels()`、`chatProviderOptions()` 和 `chatModelOptions()`。
- 将 `runPromptLLMNode()` 调整为“使用上游文本 + 生成要求 + 图片参考”的文本生成请求。
- 生成成功后仅写入 `node.text`。

### 阶段四：输入轨道与排序

- 将图片与上游文本节点统一渲染为输入轨道卡片。
- 实现稳定排序、拖拽排序和键盘左移/右移。
- 在请求构建前按输入轨道顺序合并文本节点输出。
- 图片仅作为 `images`/`videos` 参数参与多模态请求。

### 阶段五：提示词库与旧 UI 清理

- 提示词库选择结果写入生成要求字段。
- 删除或停用旧内嵌 LLM 开关、系统提示词、最终提示词预览、预设 chips 和隐藏拼接 UI。
- 搜索并移除遗留的旧 DOM class、事件绑定和未使用状态。

### 阶段六：国际化与样式

- 为“文本”“输入轨道”“生成要求”“模型平台”“文本模型”“生成中”等新增中英文词条。
- 新增专用 CSS 选择器，避免与图片/视频 Composer 或旧提示词节点样式互相覆盖。
- 使用 `:focus-visible`、明确 `aria-label`、状态文字和主题变量完成无障碍细节。

## 7. 验收清单

### 功能

- 创建文本节点后可直接输入、双击编辑、保存并重载。
- 文本节点能连接到图片、视频、文本节点，并向下游提供预期文本。
- 多个上游文本节点按输入轨道顺序合并。
- 图片输入能够随视觉语言模型请求发送。
- 仅展示已配置平台的 `chat_models`，不混入图片、视频或音频生成模型。
- 模型生成成功更新输出文本；失败保留旧输出。
- 提示词库内容写入生成要求字段。

### 交互

- 单击选中、双击编辑、节点拖拽、输入轨道排序互不冲突。
- `Ctrl/⌘ + Enter` 生成，`Shift + Enter` 换行。
- 排序支持鼠标、触摸和键盘替代操作。
- `Esc` 可关闭生成面板并将焦点返回节点。
- 生成按钮有运行、成功、失败和禁用状态。

### 视觉与无障碍

- 输入轨道、生成要求和输出文本有明确层级，不依赖颜色作为唯一提示。
- 所有图标按钮有 `title` 和 `aria-label`。
- 下拉、输入框、提示词库和生成按钮具有可见焦点样式。
- 错误在相关输入区附近显示，并通过 `aria-live` 宣告。
- 小屏无水平溢出；输入轨道可独立横向滚动。
- 明暗主题下文本、边框和状态颜色保持可读。

### 回归

- 旧 `smart-prompt`、旧多图节点、工作流导入导出和保存兼容不回归。
- 画布级联、循环、上下游文本聚合和图片参考输入不回归。
- 执行 `node --check static/js/smart-canvas.js`。
- 执行 `git diff --check`。
- 对旧提示词节点的相关变量、样式和事件进行针对性 `rg` 检查，避免残留失效 UI。
