# 提示词节点布局修复计划

日期：2026-08-11
范围：智能画布提示词/文本节点的生成面板、节点操作区、提示词标签和响应式布局

## 背景

当前文本节点已经具备：

- 可编辑的 `node.text` 输出；
- 节点下方的文本生成面板；
- 文本节点右上角的提示词库入口；
- 提示词标签和复制按钮；
- 画布视口避让顶部栏、左侧工具栏和底部视图控件的逻辑。

本轮审查发现，生成面板仍嵌套在文本节点内部，导致面板与节点边界贴合、宽度明显大于节点，并且在小屏上可能覆盖左侧工具栏或产生横向溢出。节点右上角的删除、提示词库和复制操作也依赖固定 `right` 偏移，缩放、标签增多或响应式变化后存在重叠风险。

## 目标

1. 生成面板在桌面端稳定显示在节点下方，不与节点边界重叠。
2. 面板定位不再通过反复修改画布视口来解决常规位置问题。
3. 面板宽度与文本节点形成合理比例，避免浮层过重。
4. 移动端改为底部抽屉式面板，避免左侧工具栏和画布宽度造成溢出。
5. 文本节点顶部操作区采用稳定的槽位布局，删除、提示词库和复制互不遮挡。
6. 保持现有 `node.text`、`llmInstruction`、提示词库应用和生成接口契约不变。

## 实施步骤

### 1. 生成面板定位

- 为智能画布增加独立的文本生成面板浮层容器。
- 面板通过选中文本节点的屏幕矩形定位，默认位于节点下方 14 至 16px。
- 桌面端只做水平夹取和有限的垂直避让，不再为普通越界情况反复移动 `viewport`。
- 面板在节点拖动、缩放、窗口尺寸变化和画布缩放后重新定位。
- 节点删除、取消选择或按 `Escape` 时清理浮层。

### 2. 桌面布局

- 面板最大宽度调整为约 440px，并保留 `calc(100vw - 32px)` 约束。
- 面板与节点保留明确间距，避免边框视觉重叠。
- 文本节点正文区、标签区、复制按钮和提示词库按钮使用相对定位槽位。
- 标签超过一行时只在标签区滚动，不继续挤压正文区域。

### 3. 移动布局

- 在 `max-width: 640px` 下，面板切换为固定底部抽屉。
- 抽屉宽度不超过视口，左右保留安全间距。
- 模型平台和文本模型上下排列。
- 提示词库和生成按钮提供至少 44px 的点击区域。
- 页面保持禁止横向溢出，输入轨道允许独立横向滚动。

### 4. 验收

- 桌面 1280×720：节点位于左、中、右侧时检查面板位置。
- 节点接近顶部、底部、左侧工具栏时检查遮挡和视口跳动。
- 至少通过浏览器交互验证：选中、打开提示词库、应用卡片、编辑正文、关闭面板、删除节点。
- 运行 `node --check` 检查相关 JavaScript。
- 运行 `git diff --check`，确认不引入空白错误。
- 检查现有未提交改动未被回退或混入无关文件。

## 不在本轮范围内

- 不修改文本节点的持久化字段和生成接口；
- 不重做提示词库卡片内容、分类和后端接口；
- 不新增视觉主题、在线字体或第三方 UI 框架；
- 不提交运行时数据、生成媒体或 API 配置。

## 回滚边界

本轮只涉及：

- `static/js/smart-canvas.js`
- `static/css/smart-canvas.css`
- `static/css/prompt-presets.css`
- `static/smart-canvas.html`
- 本计划文件

如浮层方案影响现有画布交互，可优先回滚面板容器和定位函数，保留节点操作区与响应式 CSS 修复。
