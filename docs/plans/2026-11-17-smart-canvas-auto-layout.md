# 智能画布「自动排版」功能开发计划书

日期：2026-11-17
状态：待评审（未动工）
需求来源：用户 m00003（附工具栏图标参考图 m00014）、m00008、m00018

## 1. 需求概述

在智能画布中为选中的多个节点提供一键批量排版能力，交互形式为工具栏图标触发（参考用户提供的对齐/分布图标条）。

已确认的两条决策：

- **触发方式**：工具栏图标触发（不做右键菜单入口）。
- **对齐基准**：左对齐以「选区中最左侧的节点」为基准；其余对齐方向同理取对应极值节点。

## 2. 功能清单

| 分组 | 功能 | 规则 |
| --- | --- | --- |
| 对齐 | 左对齐 | 所有选中节点的 `x` 取选区最小 `x` 节点的 `x` |
| 对齐 | 水平居中 | 按选区外接框的水平中线对齐 |
| 对齐 | 右对齐 | 按选区最右边缘（`x + width` 最大值）对齐 |
| 对齐 | 顶对齐 | 所有选中节点的 `y` 取选区最小 `y` 节点的 `y` |
| 对齐 | 垂直居中 | 按选区外接框的垂直中线对齐 |
| 对齐 | 底对齐 | 按选区最下边缘（`y + height` 最大值）对齐 |
| 尺寸 | 等宽 | 宽度统一为「第一个选中节点」的宽度 |
| 尺寸 | 等高 | 高度统一为「第一个选中节点」的高度 |
| 分布 | 水平等距 | 首尾节点不动，中间节点按间距均分 |
| 分布 | 垂直等距 | 首尾节点不动，中间节点按间距均分 |
| 排布 | 网格排列 | 先按第一个选中节点等宽等高统一尺寸，再按选中顺序排入网格；列数按节点数量自动取接近正方形的排布，格子间距固定 |

生效条件：选中节点数 ≥ 2（分布类要求 ≥ 3）；不足时不浮现按钮组。

## 3. UI 方案

- 位置与出现时机：**仅在多选（≥2 个节点）时浮现**一组排版按钮（参考用户提供的对齐/分布图标条样式），单选或无多选时不显示；实现上挂在现有多选浮动工具条或等效位置。
- 图标：Lucide 既有图标集内选择（align-start / align-center / align-end / distribute / grid 等）。
- 悬停显示中文提示，词条加入 `static/js/i18n/smart-canvas.js` 并同步英文词条，跑 `node static/js/i18n/validate-i18n.js` 校验完整性。
- 动态插入图标后沿用既有 `lucide.createIcons()` / `refreshIcons()` 模式。

## 4. 技术要点（必须遵守的项目边界）

依据 AGENTS.md「协作同步与授权不变量」与「画布持久化与兼容」：

1. **细粒度操作提交**：排版产生的每个节点位移/尺寸变化，都以既有的节点字段更新操作（`updateNode` 形式的窄操作）逐条提交并广播，绝不回写整张画布快照。
2. **撤销支持**：执行前调用一次 `pushUndo()`，整个批处理算一步撤销历史；批内用 `undoSuppressed` 抑制逐节点入栈，完成后统一 `render()` + `scheduleSave()`。
3. **组织框（smart-workflow-group）**：框与成员视为原子集合——对齐/分布/网格排列时，框连同成员整体移动且相对位置不变（与现有「自动整理把组织框和成员当作原子集合」的规则保持一致）。等宽/等高不作用于组织框（其尺寸由成员包围盒决定）；网格排列时组织框按原始大小参与占位，不强制缩放。
4. **纯前端几何计算**：坐标换算全部在前端完成，服务端无需改动路由；保存链路复用现有画布操作流，所有权与编辑权限校验走现有统一画布访问校验。
5. **兼容性**：不新增节点持久化字段；若实现上确需新字段，必须提供默认值，保证旧画布可正常加载/保存/重载。
6. **等宽/等高与网格的尺寸写法**：优先复用现有的节点缩放途径（如 scale 相关字段），避免直接改写图片节点的内容尺寸导致媒体比例失真——具体挂钩点在实现阶段核对 `smart-canvas.js` 现有 resize 逻辑后确定。

## 5. 实施步骤

1. 调研：通读 `static/js/smart-canvas.js` 中选中集管理、`pushUndo`、节点更新操作提交与广播、现有「自动整理」的实现，确认排版函数接入点与可复用的 helper。
2. 实现核心算法模块：`applyAlign(mode)` / `applyDistribute(axis)` / `applyEqualSize(dim)`，输入为当前选中节点集合。
3. 接入工具栏 UI 与 i18n 词条。
4. 编写/更新测试：至少覆盖对齐基准计算、分布均分、组织框整体移动、撤销一步还原（前端逻辑以定向测试 + 浏览器实测结合）。
5. 语法与卫生检查：`node --check` 全量 JS、i18n 校验、`git diff --check`。
6. 浏览器实测验收（见第 6 节），完成后按项目规则创建独立 Git commit。

## 6. 验收清单

- [ ] 仅多选（≥2）时浮现排版按钮组；单选/无选中不出现。
- [ ] 左/右/顶/底对齐结果符合「极值节点为基准」的定义；水平/垂直居中外接框中线正确。
- [ ] 水平/垂直等距：首尾固定，相邻间隙相等。
- [ ] 等宽/等高：尺寸统一为第一个选中节点的宽/高，且不破坏节点内容显示。
- [ ] 网格排列：先等宽等高（基准=第一个选中节点）再入格，按选中顺序排列，列数接近正方形，间距一致。
- [ ] 包含组织框时：框连同成员整体移动，成员相对布局不变；组织框不被强制缩放。
- [ ] 双标签页同时打开同一画布：A 执行排版后 B 实时收到节点位置更新；B 的迟到操作不会覆盖排版结果（最后有效操作胜出）。
- [ ] 排版后刷新页面：位置持久化正确。
- [ ] Ctrl+Z 一步撤销整个排版（含网格排列的尺寸统一）；重做行为正常。
- [ ] 无编辑权的协作者看不到可用的排版按钮，且伪造请求被服务端拒绝。

## 7. 已确认决策（2026-11-17，用户 m00031）

1. 等宽/等高基准：取**第一个选中节点**的尺寸。
2. 按钮出现时机：**多选时浮现**，非常驻。
3. **加入网格排列**：网格排列时节点自动等宽等高，同样以第一个选中节点为标准。

## 8. 风险与回滚

- 风险集中在批量操作与实时同步的交互：若逐条窄操作引发高频广播，考虑合并为单个批量操作消息（沿用仓库现有批量操作格式，实现阶段确认）。
- 功能为纯增量，出现问题可整体移除入口按钮回滚，不影响既有画布数据。
