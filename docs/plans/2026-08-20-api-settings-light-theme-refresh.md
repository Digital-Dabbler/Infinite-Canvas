# API 设置页浅色主题视觉刷新

**日期：** 2026-08-20
**状态：** 第一至三阶段已实施；等待浏览器验收
**范围：** `static/api-settings.html`、`static/css/api-settings.css`

## 背景与目标

API 设置页保留现有的 Master–Detail 结构、Provider 编辑/推荐视图切换、配置组权限模型和所有保存逻辑。本次只刷新浅色主题的视觉层级与状态语义，让凭据和平台管理更接近可信、克制的技术控制台，而不是通过高饱和色或大量白卡抢占注意力。

## 已识别问题

1. 绿色同时代表当前 Provider 选中、已配置状态和图标强调，选中与成功语义混淆。
2. 顶部配置组、详情标题、基础信息、Key 区块和输入框连续使用白底与细边框，层级过平。
3. 左侧 Provider 导航、推荐 API 和保存操作的视觉权重不够明确。
4. Key 区块和图标操作较密集，输入、敏感凭据与危险操作的层级不足。
5. 浅色主题的焦点环、只读/编辑表面和辅助文本对比度需要统一规范。

## 设计方向：Calm Technical Console

- 使用中性灰白作为页面与内容层级，减少不必要的卡片阴影。
- 深海军蓝只用于主提交操作；蓝色只用于当前导航项与键盘焦点。
- 绿色只用于“已配置/验证通过”等成功状态，不再表示当前选中。
- 保留当前紧凑密度，优化浏览顺序，而不重构表单数据和交互流程。

## 实施规则

### 页面与表面

- 顶部配置组保留为上下文条：标签与说明靠左，选择控件靠右。
- 右侧详情保持一个轻量标题头；基础信息和模型配置仍可作为区块，但取消堆叠式重阴影。
- 凭据相关 `.key-panel` / `.rh-key-item` 使用次级表面，明确区别普通字段与敏感配置。

### Provider 导航

- `.api-nav-item.active` 使用浅蓝背景、蓝色边界与左侧条；不使用绿色。
- 成功点继续使用绿色；未配置状态维持中性灰。
- 推荐入口保留深海军蓝的提交/引导外观，但避免与 Provider 选中语义混用。

### 控件与无障碍

- 输入框使用白色编辑表面与 `#CBD5E1` 边界；获得焦点时显示蓝色边界与 3px 柔和焦点环。
- 所有键盘焦点统一使用蓝色 `:focus-visible`，不删除浏览器可发现的焦点提示。
- 删除和清除保留红色语义，并使用低饱和浅红 Hover 背景。
- 标题使用语义化 `h1`，不影响现有 i18n 或脚本定位。

## 第二阶段实施记录

本阶段已在不改变保存请求和权限模型的前提下补齐交互反馈：

- 顶部状态区现在仅在存在状态文本时显示，并提供 `role="status"` 与 `aria-live="polite"`。
- 编辑字段会展示“有未保存更改”；保存时按钮进入禁用的“保存中”状态，成功后显示“已保存”，失败显示错误状态。
- Provider 导航按钮现在具有状态文本的无障碍名称与悬浮说明：已配置、未配置、已停用或本机登录态；颜色点仍只作为辅助。
- 页面级保存按钮改为“保存更改”；不修改现有 `saveProviders()` 请求契约。

## 第三阶段实施记录

补齐此前尚未落实的可见信息层级：

- 配置组选择器现放入“正在编辑”上下文控件，并在窄屏中换为独立的顶部行。
- Provider 列表将凭据状态作为可见第三行文本（并保留色点和无障碍名称），不再只把状态藏在 tooltip 或屏幕阅读器文本中。
- 通用 API Key、RunningHub 的两类 Key、火山方舟 Key 与火山素材库 AK/SK 都获得状态 Badge；AK/SK 只保存其一时明确显示“配置不完整”。
- 所有静态带 `title` 的图标按钮会同步到 `aria-label`，语言切换后会重新同步。
- 详情区的常规基本信息、工作流和模型区块已改为单一编辑表面中的分隔 section；只有凭据卡继续作为浅色提升表面。

## 非目标

- 不更改 API Profile、Provider、Key、模型、推荐页或本地服务的业务逻辑。
- 不修改权限控制、凭据存储、保存请求、路由或接口返回。
- 不同步更改全局深色主题 token，也不手工更新静态资源 `?v=` 缓存戳。
