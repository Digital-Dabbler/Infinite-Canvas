# Infinite Canvas Photoshop Bridge 开发基线

> 状态基线：0.2.7
> 记录日期：2026-07-31
> 适用目录：`tools/photoshop-canvas-bridge/` 及 `main.py` 中的 `/api/photoshop-bridge/*`

本文档是插件后续开发的产品与技术边界。修改 Bridge 前应先阅读本文；如果需求需要改变这里的原则，应先更新本文并说明取舍，而不是在实现中悄悄改变行为。

## 一句话目标

让 Infinite Canvas 与 Photoshop 在本机或局域网中可靠、低打扰地双向交接图片，同时兼容 Photoshop CC 2018 到当前版本，并确保传输不会修改用户原文档。

## 当前产品形态

Bridge 是独立的 Photoshop CEP 面板，不依赖、不替代现有的 `photoshop-asset-connector` UXP 素材库面板。

### 画布 → Photoshop

- 智能画布图片通过“发送到 Photoshop”创建服务端交接任务。
- 当前账号下的所有在线 Bridge 实例都能实时收到任务并更新收件箱。
- 同一任务只允许一个 Photoshop 实例成功认领并自动打开，避免同账号多台电脑重复弹出文档。
- 新任务默认打开为 Photoshop 新文档。
- 收件箱支持预览、再次打开为新文档，以及作为智能对象置入当前文档。
- 收件箱展示当前账号最近 7 天、最多 50 条记录。

### Photoshop → 智能画布

- 用户显式选择目标智能画布后发送当前 Photoshop 文档。
- 有选区时按选区最外围矩形裁切；没有选区时发送整张合并画面。
- 小于 64px 的选区需要二次确认。
- 导出在临时副本中完成，不能修改原文档、图层或选区。
- 每次发送在目标智能画布创建新的 `smart-image-upload` 节点，不覆盖已有节点。

## 不可破坏的产品约束

### 1. 实时优先，但不能用高频轮询换取“看起来实时”

- 正常更新依赖带认证的 `/ws/stats` WebSocket。
- 客户端使用应用层心跳：每 15 秒发送一次轻量 `ping`，45 秒无任何消息视为失联并重连。
- 首次连接和断线重连时允许通过 REST 补拉一次任务。
- 不允许恢复常驻的高频收件箱轮询。确有必要增加定时校验时，必须先给出资源数据和失败场景，并采用分钟级、无变化不重绘的策略。

### 2. “一键清除”是本地视图操作

- 清除后，当前面板会隐藏已经显示的任务。
- WebSocket 重连或自动补拉不能让这些任务立即重新出现。
- 用户手动点击刷新时解除隐藏并恢复服务端最近记录。
- 清除不会删除服务端任务，也不会影响其他电脑或其他账号。
- 如果未来需要“永久删除记录”，必须设计单独、明确命名并带确认的服务端操作，不能改变现有“一键清除”的语义。

### 3. 多电脑连接必须彼此可见，但自动打开必须防重

- WebSocket 身份由“用户 ID + Bridge 类型 + 客户端实例 ID”共同区分，不能让一台电脑覆盖另一台电脑的连接。
- 服务端向同账号所有 Bridge 实例广播任务，使各端收件箱都能及时更新。
- 任务通过 `client_instance_id` 认领；只有最先成功认领的实例自动打开。
- 认领租约当前为 2 分钟。打开失败或租约过期后允许重试。
- 不要为了让每台电脑都弹出文档而绕过认领；如产品目标改变，应先重新定义多设备交互。

### 4. 账号与数据隔离

- 任务、状态和收件箱按 Infinite Canvas 登录账号隔离。
- REST、媒体下载和 WebSocket 都必须使用服务端认证。
- 不在 URL、日志、响应或插件包中写入上游 API Key、Cookie 或固定访问令牌。
- 切换账号时必须关闭旧连接、清理旧 token 和旧账号的本地收件箱状态。

### 5. Photoshop 兼容性优先

- 必须继续支持 Windows Photoshop CC 2018（v19）、2024 和 2025。
- 保持 CEP 7 schema、CSXS 7 最低运行时、ExtendScript 和 ES5 兼容写法。
- 客户端代码不引入需要构建的框架，不使用 CC 2018 内置 Chromium/ExtendScript 不支持的语法或 CSS。
- 不迁移到 UXP，除非明确放弃 CC 2018 并完成独立产品决策。

### 6. 原文档安全

- Photoshop 导出必须基于临时副本并扁平化。
- 任何发送、裁切、预览或失败重试都不能改变用户原文档、图层、选区、保存状态或文件位置。
- 画布传入图片与 Photoshop 文档之间不建立隐式长期绑定。

## 当前技术结构

```text
智能画布右键发送
  → POST /api/photoshop-bridge/tasks
  → 持久化 data/photoshop_bridge_tasks.json
  → 向账号下所有 Bridge 实例推送 photoshop_edit_requested
  → 实例竞争 POST .../claim
  → 获胜实例下载认证媒体并调用 bridgeOpenDocument
  → POST .../opened 或 .../open-failed
```

主要文件：

| 文件 | 职责 |
| --- | --- |
| `main.py` | 任务持久化、账号隔离、多实例推送、认领、完成、回传和安装包下载 |
| `client/js/app.js` | 登录、实例 ID、WebSocket/心跳、收件箱、自动打开、预览和发送流程 |
| `client/js/net.js` | REST、Bearer 认证与媒体下载 |
| `client/js/cep.js` | CEP Persistent 和 ExtendScript 调用封装 |
| `host/index.jsx` | Photoshop 打开、置入、文档状态、选区与临时副本导出 |
| `tests/test_photoshop_bridge.py` | 后端状态机、兼容约束和关键客户端行为回归检查 |

服务端任务是跨重启和跨设备的事实来源；面板内的任务数组、隐藏记录和对象 URL 只是当前窗口状态。

## 当前资源策略

- 空闲在线时只有 15 秒一次的心跳文本，不下载任务列表或缩略图。
- 新任务由 WebSocket 单条推送。
- 仅首次连接、重连恢复或用户手动刷新时拉取最近任务。
- 缩略图按界面需要下载并使用对象 URL；任务离开可见集合时释放对象 URL。
- Photoshop 文档状态当前每 1.5 秒读取一次，用于及时更新“发送到画布”按钮和选区信息。若后续发现宿主调用开销明显，应优先改为面板聚焦/文档事件驱动，而不是降低收件箱可靠性。

## 明确不做的事情

- 不把 Bridge 扩展成完整素材库；素材管理属于 `photoshop-asset-connector`。
- 不默认双向实时同步 Photoshop 文档与画布节点。
- 不在收到任务时自动覆盖、置入或修改当前 Photoshop 文档。
- 不让同一任务在同账号的每台 Photoshop 上同时自动弹出。
- 不通过高频 REST 轮询掩盖 WebSocket、鉴权或多实例路由问题。
- 不把“一键清除”变成服务端永久删除。
- 不因视觉优化引入前端构建链或牺牲 CC 2018 兼容性。

## 后续开发目标

按优先级排序：

1. **可靠交接**：本机与局域网行为一致；断网、休眠、服务重启后能恢复；不重复打开、不漏掉新任务。
2. **状态可解释**：清楚区分未连接、连接中、在线、重连、打开失败和被其他实例认领，避免绿点与真实状态不一致。
3. **低资源占用**：无高频任务轮询，无无效 DOM 重绘，及时释放临时对象 URL 和临时文件。
4. **失败可恢复**：下载失败、Photoshop 打开失败、认领租约过期均可重试，且错误能在卡片或状态栏看到。
5. **安装可维护**：版本号、README、清单和 ZIP 文件名一致，覆盖安装路径稳定，公司共享目录始终能取得最新版。
6. **兼容性稳定**：每次修改均检查 CC 2018 可用的 JavaScript、CSS、CEP 和 ExtendScript 能力。

## 变更验收清单

涉及 Bridge 的改动至少确认：

- [ ] 画布发送的新图片能在局域网 Photoshop 收件箱实时出现。
- [ ] 新任务只在一个同账号实例中自动打开，其他实例不重复弹窗。
- [ ] 隐藏/折叠面板后仍能接收；断网恢复后能补拉遗漏任务。
- [ ] 一键清除后记录不会自动复现；手动刷新能够恢复。
- [ ] 空闲时没有高频 `/api/photoshop-bridge/tasks` 请求。
- [ ] 打开新文档、智能对象置入、整图发送和选区发送均正常。
- [ ] 发送过程不修改 Photoshop 原文档。
- [ ] 切换账号后旧账号记录、token 和连接不会残留。
- [ ] `node --check tools/photoshop-canvas-bridge/client/js/app.js` 通过。
- [ ] `.\python\python.exe tests\test_photoshop_bridge.py` 通过。
- [ ] 新 ZIP 中包含本次源码，且版本号与 `CSXS/manifest.xml` 一致。
